# way2AIPM OS v0.27 LangGraph Runtime 页面集成规格

## Summary

v0.27 将 v0.26 已验证的 LangGraph 受控复盘试点接入现有 Workflow 页面，让一条面试后修复流程可以在工作台内完成：

```text
WorkflowRun
  -> 页面发起受控诊断
  -> LangGraph review_specialist 调用现有 AI 诊断 API
  -> approval_gate interrupt 等待人工审批
  -> 页面逐条选择采纳或忽略
  -> approval_commit 仅写入已采纳的缺陷与训练任务
  -> 页面展示已完成的 Runtime 结果
```

Markdown 仍保存业务事实，`runtime/langgraph/checkpoints.json` 只保存本地运行状态。页面不是自由聊天入口，也不会自动运行或自动批准 AI 建议。

## Goals

- 在 Workflow 详情中显示 LangGraph Runtime 状态，并提供发起诊断入口。
- 通过服务端 API 启动、查询和恢复指定 `WorkflowRun.id` 对应的运行线程。
- 把审批从试点命令行的 `accept_all` 扩展为缺陷候选和训练候选逐条 `accept` / `ignore`。
- 在 interrupt 期间不写入缺陷或训练任务，只有提交人工决定后才复用现有 `candidate-actions` 写回。
- 对缺少模型配置、模型请求失败、非法候选组合等错误提供可见提示，并允许在页面重试。
- 保持 v0.26 命令行试点与幂等写回验证仍可运行。

## Non-Goals

- 不增加自动审批、自动关闭流程或多 Agent 自动调度。
- 不实现面试前专项 Agent。
- 不引入数据库、登录、权限或云端部署。
- 不开放 checkpoint 原始内容，也不将其作为领域数据导出。
- 不替换现有 AI 分析工作台中的手动候选处理入口。

## Runtime API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/api/workflow-runs/:id/runtime` | 返回当前流程的 Runtime 摘要与待审批候选；未启动时返回 `not_started`。 |
| `POST` | `/api/workflow-runs/:id/runtime/start` | 启动受控诊断；生成候选后停在 `waiting_for_approval`。 |
| `POST` | `/api/workflow-runs/:id/runtime/resume` | 接收人工决定并恢复运行；完成后返回写回结果。 |

`resume` 请求体：

```json
{
  "action": "commit",
  "decisions": [
    { "candidateType": "weakness", "candidateId": "weakness_candidate_1", "action": "accept" },
    { "candidateType": "training_task", "candidateId": "training_candidate_1", "action": "ignore" }
  ]
}
```

规则：

- 页面提交时必须覆盖本次诊断的全部候选；不允许以未选择作为默认忽略。
- 训练任务被采纳时，其关联缺陷候选也必须被采纳。
- `defer` 仅作为已有试点兼容动作保留，不在页面作为主要审批操作展示。
- API 不向浏览器返回密钥、模型端点或 checkpoint 文件内容。

## UI Interaction

Workflow 详情增加 `受控 AI Runtime` 区域：

- `not_started`：显示“生成受控诊断”按钮。
- `waiting_for_approval`：显示诊断摘要、缺陷候选和训练候选；每条候选使用选项控件选择“采纳”或“忽略”；全部完成选择后可提交审批。
- `completed`：显示本次审批决定与已生成业务记录数量；现有“查看 AI 诊断”和关联资产入口仍可使用。
- 处理中按钮禁用，失败通过 toast 告知，并保留重新启动或重新提交的能力。

## Storage And Boundary

- 领域数据继续保存在 `content/` 下的 Markdown 文件。
- Runtime checkpoint 默认保存在 Git 忽略目录 `runtime/langgraph/checkpoints.json`。
- LangGraph 节点能力保持隔离：

| 节点 | 允许能力 | 写入边界 |
| --- | --- | --- |
| `orchestrator` | 调度复盘节点 | 无写入 |
| `review_specialist` | 创建/复用 AI note 并调用诊断 API | 仅生成可审查候选 |
| `approval_gate` | `interrupt()` 和决策校验 | 无写入 |
| `approval_commit` | 按明确决策调用现有候选处理 API | 仅采纳项产生业务记录 |

## Acceptance Criteria

- Workflow 页面可以启动 Runtime，并在 AI 候选生成后显示等待审批状态。
- 页面启动后的 interrupt 阶段不产生缺陷或训练任务记录。
- 用户能够逐条采纳或忽略候选；未选择完整时不能提交。
- 采纳训练任务而忽略关联缺陷会被拒绝并提示修正决定。
- 提交审批后只创建被采纳记录，刷新页面仍能读取 completed Runtime 摘要。
- 重复读取或恢复已完成线程不会重复写入业务记录。
- 本地 smoke test 通过服务端 Runtime API 验证启动、查询、逐条审批与幂等结果。
