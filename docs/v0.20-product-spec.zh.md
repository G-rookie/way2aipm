# way2AIPM OS v0.20 AI 契约与人工确认机制规格

## Summary

v0.20 聚焦正式 AI 接入前的最后一个基础能力：把外部 AI 的文本结果变成可解析、可审查、可选择采纳的结构化候选。

本版优先覆盖“面试复盘分析”场景：

```text
面试复盘
  -> 生成包含 JSON schema 的提示词
  -> 手动粘贴外部 AI 返回的 JSON
  -> 系统解析成缺陷候选和训练任务候选
  -> 用户逐条采纳或忽略
  -> 采纳后才写入能力缺陷/训练任务 Markdown
```

本版仍不调用外部 AI API。

## Goals

- 新增 AI 分析类型：`review_diagnosis`（复盘诊断）。
- 为 `interview_review + review_diagnosis` 生成结构化 JSON 输出要求。
- 扩展 AI 分析记录字段：
  - `candidateSchemaVersion`
  - `structuredResponse`
  - `weaknessCandidates`
  - `trainingTaskCandidates`
- 新增结构化解析 API：
  - `POST /api/ai-analysis-notes/:id/parse-candidates`
- 新增人工动作 API：
  - `POST /api/ai-analysis-notes/:id/candidate-actions`
- AI 分析工作台展示候选列表和状态：
  - 待确认
  - 已采纳
  - 已忽略
- 采纳缺陷候选时创建真实能力缺陷记录。
- 采纳训练候选时创建真实训练任务记录；必须先关联已采纳的缺陷候选。
- 任何候选写入业务模块前都必须经由用户动作。

## Non-Goals

- 不调用 OpenAI 或其他模型 API。
- 不自动采纳任何 AI 建议。
- 不自动覆盖现有复盘、缺陷或训练记录。
- 不处理所有 AI 分析类型的结构化输出。
- 不迁移数据库或 Next.js。
- 不增加删除能力。

## Schema

当分析类型为 `review_diagnosis` 且来源为 `interview_review` 时，期望粘贴的 JSON：

```json
{
  "summary": "本次面试整体诊断",
  "failurePoints": ["挂点 1"],
  "weaknessCandidates": [
    {
      "title": "项目指标表达不够具体",
      "category": "project_depth",
      "severity": "high",
      "evidence": "面试中未能回答指标变化",
      "description": "缺少用结果证明判断的表达结构"
    }
  ],
  "trainingTaskCandidates": [
    {
      "title": "重写指标结果回答",
      "weaknessCandidateIndex": 0,
      "taskType": "answer_rewrite",
      "targetAbility": "用数据说明产品判断",
      "practiceOutput": "一版两分钟回答稿",
      "acceptanceCriteria": "能说明目标、动作、指标变化与反思"
    }
  ]
}
```

服务端将候选标准化，并添加：

- `id`
- `decision`: `pending | accepted | ignored`
- `createdWeaknessId` 或 `createdTrainingTaskId`

## Interaction

### 解析候选

- 用户先保存 AI 分析记录。
- 用户将符合 schema 的 JSON 粘贴到“结构化 AI 输出”。
- 点击“解析结构化候选”。
- 解析失败时只报错，不写入业务模块。

### 采纳缺陷候选

- 点击“采纳为能力缺陷”。
- 系统创建 `content/weaknesses/{id}.md`。
- 缺陷自动关联来源复盘。
- 候选标记为已采纳，并保留生成的缺陷 ID。

### 采纳训练候选

- 候选必须指向一个缺陷候选。
- 只有该缺陷候选已经采纳并生成真实缺陷，训练候选才可采纳。
- 采纳后生成 `content/training-tasks/{id}.md` 并关联真实缺陷。

### 忽略候选

- 点击忽略后只更新 AI 分析记录中的 decision，不删除任何文件。

## Test Plan

- `node --check server.mjs`
- `node --check public/app.js`
- `git diff --check`
- 创建复盘诊断 AI 记录并保存 Markdown。
- 解析有效 JSON 后，候选写入 AI 分析记录。
- 解析无效 JSON 时返回清晰错误。
- 采纳缺陷候选后，生成单个 weakness Markdown 并关联来源复盘。
- 未采纳缺陷前尝试采纳训练候选应失败。
- 采纳训练候选后，生成单个 training task Markdown 并关联缺陷。
- 忽略候选只更新分析记录，不生成业务文件。
