# way2AIPM OS v0.22 Workflow Foundation 产品规格

## Summary

v0.22 暂停扩张新的 AI 场景，先为 `way2AIPM OS` 增加可见、可追踪、可恢复演进的 Workflow 基础层。

首个流程是 `post_interview_repair_loop`：

```text
已保存复盘
  -> 开启修复流程
  -> 生成复盘诊断候选
  -> 人工采纳缺陷/训练任务
  -> 执行训练
  -> 等待真实验证
  -> 关闭闭环
```

本版使用现有 Node 服务与 Markdown 存储实现轻量状态机，不引入外部 Agent Runtime。实现结果将作为后续 Agent 工具层与开源 Runtime 适配验证的真实依据。

## Goals

- 引入一级对象 `WorkflowRun`，让一次修复闭环拥有自己的状态和时间线。
- 支持从一条已保存的 `InterviewReview` 手动开启修复流程。
- 将 v0.21 已有的 AI 诊断与候选人工确认能力纳入流程状态。
- 在总控调度器中展示运行中的 Workflow 与当前等待动作。
- 提供流程详情视图，可从流程跳转到关联复盘、AI 诊断、缺陷与训练任务。
- 保持所有关键业务写入的人工确认边界。

## Non-Goals

- 不引入 LangChain、LangGraph 或新的 npm 依赖。
- 不提供通用可视化流程编辑器。
- 不让 Agent 自主调用写入型工具。
- 不实现面试前 JD 拆解或问题预测的 AI 扩展。
- 不改为数据库存储。
- 不提供删除或批量清理流程记录。

## Workflow Definition

定义键：

```text
post_interview_repair_loop
```

状态：

| Status | 当前阶段 | 下一步 |
| --- | --- | --- |
| `diagnosis_pending` | 已创建流程，尚无候选 | 生成 AI 诊断或手动解析 |
| `candidate_confirmation` | 候选待决定 | 采纳/忽略缺陷与训练候选 |
| `training_pending` | 已创建训练任务 | 开始训练 |
| `training_in_progress` | 训练中 | 完成验收 |
| `validation_pending` | 训练已验证 | 用下一次面试验证修复效果 |
| `completed` | 闭环已完成 | 查看总结 |
| `paused` | 流程暂停 | 恢复推进 |

## Data Model

目录：

```text
content/workflow-runs/{id}.md
```

字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 流程运行 ID |
| `definitionKey` | 固定为 `post_interview_repair_loop` |
| `title` | 流程名称 |
| `status` | 当前流程状态 |
| `opportunityId` | 关联岗位 |
| `interviewRoundId` | 关联面试轮次 |
| `reviewId` | 关联复盘 |
| `aiAnalysisNoteId` | 关联复盘诊断记录 |
| `weaknessIds` | 已确认创建的缺陷 |
| `trainingTaskIds` | 已确认创建的训练任务 |
| `currentStep` | 当前步骤 |
| `waitingFor` | `human_action | ai_generation | training | validation | none` |
| `events` | 状态变化时间线 |
| `summary` | 闭环总结 |
| `createdAt` / `updatedAt` | 时间戳 |

## API

- `GET /api/workflow-runs`
- `GET /api/workflow-runs/:id`
- `POST /api/workflow-runs`
  - 输入 `reviewId`。
  - 校验复盘存在。
  - 同一复盘已有活动流程时返回该流程，避免重复创建。
- `PUT /api/workflow-runs/:id`
  - 用于暂停、恢复、完成与总结维护。

既有动作的流程同步：

- AI 复盘诊断解析成功后，关联流程进入 `candidate_confirmation`。
- 候选采纳并产生训练任务后，关联流程进入 `training_pending`。
- 训练任务开始或完成后，重新计算关联流程状态。

## UI

### 面试后复盘室

- 在已保存的复盘记录中增加“开启修复流程”。
- 若该复盘已有流程，入口改为“查看修复流程”。

### 总控调度器

- 新增“进行中的流程”区块。
- 每条流程展示当前状态、等待动作、关联岗位/轮次和进入详情按钮。

### Workflow 详情

- 展示当前阶段和下一步。
- 展示关联复盘、AI 诊断、能力缺陷与训练任务入口。
- 展示事件时间线。
- 提供暂停、恢复和关闭流程动作。

## Acceptance Criteria

- 可从已保存面试复盘创建单条 Workflow Run Markdown。
- 同一复盘不会重复创建多个活动流程。
- Run 能展示当前状态和时间线。
- 从 Run 可进入现有复盘诊断 AI 流程。
- AI 诊断解析成功后 Run 进入待确认阶段。
- 采纳训练候选生成训练任务后 Run 进入待训练阶段。
- 总控台可看见运行中的流程及待办。
- 不会因 Workflow 创建或推进而绕过人工采纳机制。
- 不提供删除入口。

## Follow-Up

- `v0.23`：优先验证 OpenClaw Runtime、受控工具层与复盘专项 Agent。
- `v0.24`：依据验证结果，将已验证流程映射到 OpenClaw Task Flow，或转验候选方案。
- `v0.25`：Runtime 路线确认后，再加入面试前准备 Agent Workflow。
