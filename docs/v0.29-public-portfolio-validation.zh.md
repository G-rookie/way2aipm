# v0.29 公开作品集出口与迁移边界验证记录

## 状态

- 日期：`2026-05-27`
- 分支：`codex/feature-public-portfolio-v0.29`
- 契约：`public_portfolio_v1`
- 结论：`sanitized_public_portfolio_boundary_integrated`

## 本轮交付

- 新增 `GET /api/public-portfolio` 只读输出，作为未来公开展示与 Next.js 页面的唯一数据契约。
- 使用个人资料 `published_ready` 与项目 `portfolio + ready` 的双层人工门禁。
- 公开项目输出只保留案例展示字段，排除内部项目来源、证据、隐私备注和编辑状态。
- 新增 `/showcase.html` 独立作品集展示面，不加载内部 OS 的编辑数据。
- 作品集工作台新增公开展示入口，并将内部预览与公开结果区分展示。

## Next.js 迁移验证结论

本版不直接安装或迁移 Next.js。验证结果是公开页面已经具有可独立迁移的读取边界：

| 未来 Next.js 部分 | v0.29 可复用边界 |
| --- | --- |
| `app/portfolio/page.tsx` 或公开首页 | 消费 `public_portfolio_v1` 中的 `profile` 与 `projects` |
| Server Component / Route Handler | 调用只读公开契约，不直接遍历 Markdown 文件 |
| 内部管理工作台 | 继续保留现有本地服务和写入 API，不进入首次迁移范围 |
| 数据库迁移 | 不作为展示页迁移前置条件，未来替换契约背后的存储实现 |

因此 v0.30 可以只建立 Next.js 公开读页面试点，验证路由、部署与适配成本，而无需先改写当前 OS。

## 已证实边界

- 资料处于草稿状态时，公开 API 返回未发布状态，不泄露资料正文或项目标题。
- 资料允许公开后，仅 `visibility=portfolio` 且 `readiness=ready` 的项目进入公开结果。
- 公开项目对象不含 `projectAmmoId`、`projectName`、`evidence`、`privacyNote`、`visibility` 或 `readiness`。
- 公开 API 不接受写入方法；编辑和发布决定继续只在内部工作台发生。
- 烟测会恢复已有资料文件，并仅删除自身创建的一份明确临时项目文件，不保留业务数据。
- 使用本地 Playwright 检查 `1440 x 1260` 桌面页面与 `390 x 1260` 窄屏页面，公开 Hero、项目案例与联系区域无溢出或遮挡；内部作品集工作台可见“公开展示页”入口。
