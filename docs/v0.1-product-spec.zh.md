# way2AIPM OS v0.1 产品规格

## 1. 产品定位

`way2AIPM OS` 是一个面向 AI PM 求职与成长的个人作战系统。

第一版不是公开博客，也不是完整作品集，而是一个私用优先的求职闭环工具：

```text
求职 Pipeline
  -> 面试前作战室
  -> 面试后复盘室
  -> 能力缺陷档案
  -> 训练计划中心
  -> 下一轮面试验证
```

它的目标是先帮助你真实推进投递、准备、面试、复盘和训练。未来再从这些私有记录中筛选出成熟内容，沉淀成公开作品集和成长档案。

## 2. v0.1 目标

构建一个轻量、本地优先的系统，用来管理 AI PM 求职机会、准备面试、复盘真实表现、沉淀能力缺陷，并把缺陷转化为可执行的训练任务。

v0.1 只验证一个核心问题：

> 这套系统能不能让每一次面试都变成下一次面试的训练资产？

## 3. 产品原则

### 3.1 流程优先，不只是存储

系统不应该只是一个笔记仓库。每个模块都要对应一个可重复执行的工作流程，并且明确：

- 什么时候触发
- 输入是什么
- 处理步骤是什么
- 输出什么
- 怎么判断完成

### 3.2 先私用，后公开

第一用户是你自己，所以记录可以粗糙、战术、真实。

未来公开展示的内容，不应该直接暴露整个私有系统，而是从里面筛选出成熟的项目、复盘和方法论。

### 3.3 先跑通一个闭环

v0.1 不追求覆盖完整 OS。先让求职主线跑起来，再逐步扩展 AI 前沿、作品集、节奏管理等模块。

### 3.4 用证据替代感觉

面试表现不能只靠“感觉不错”或“感觉挂了”来判断，而要沉淀成具体证据：

- 面试官问了什么
- 我怎么回答的
- 哪些回答强
- 哪些回答弱
- 弱回答背后的能力缺陷是什么
- 这个缺陷有没有训练任务
- 下一轮是否真的改善了

## 4. v0.1 范围

### 4.1 包含

- 总控台 / Dashboard
- 求职项目管理中台 / Job Pipeline
- 面试前作战室 / Pre-Interview Room
- 面试后复盘室 / Post-Interview Review
- 能力缺陷档案 / Weakness Archive
- 训练计划中心 / Training Plan Center

### 4.2 暂不包含

- 完整 AI 前沿思维框架
- 公开作品集产品线
- 个人节奏运营官
- 独立表达稳定性训练室
- 真正自动化的总控调度器
- 登录、权限、云同步、多人协作
- 自动爬取 JD 或公司信息

## 5. 核心模块

### 5.1 总控台

#### 定位

总控台是 v0.1 版本的 `00_总控调度器`。

第一版不做复杂自动化，它只负责把当前最重要的任务浮出来，让你快速知道下一步该做什么。

#### 触发场景

你打开系统，想判断今天应该先处理什么。

#### 输入

- 进行中的岗位机会
- 即将到来的面试
- 待复盘的面试
- 未修复的能力缺陷
- 进行中的训练任务

#### 输出

- 今日重点
- 待准备面试
- 待跟进机会
- 待复盘面试
- 待完成训练任务

#### 完成标准

你打开系统后，能在 30 秒内回答：

> 我现在最应该推进哪件事？

#### 反模式

- 把首页做成装饰性落地页
- 一上来堆很多没有决策价值的图表
- 看起来信息很多，但没有明确下一步动作

### 5.2 求职项目管理中台

#### 定位

求职中台是整个系统的 PMO 层，负责管理岗位机会、阶段、优先级、风险和下一步动作。

#### 触发场景

- 收集到一个新 JD
- 投递了一个岗位
- 收到面试邀约
- 面试进度发生变化
- 需要决定下一步跟进动作

#### 输入

- 公司名称
- 岗位名称
- JD 链接或 JD 原文
- 来源
- 当前阶段
- 优先级
- 风险等级
- 下一步动作
- 下一步截止时间

#### 输出

- 岗位机会记录
- Pipeline 列表或看板
- 下一步动作队列

#### 完成标准

每个进行中的岗位，都有明确的阶段、优先级、风险和下一步动作。

#### 反模式

- 所有岗位都同等对待
- 只收藏 JD，但没有下一步动作
- 岗位、面试准备、复盘和训练任务之间断开

### 5.3 面试前作战室

#### 定位

面试前作战室把一次面试邀约转化为一份可执行的面试作战 Brief。

#### 触发场景

- 某个岗位进入 `invited`
- 某轮面试已经排期
- 某个岗位进入 `preparing`

#### 输入

- 岗位机会
- 公司信息
- JD
- 面试轮次类型
- 个人项目素材
- 已知能力缺陷

#### 流程

1. 梳理公司与业务背景
2. 拆解 JD 的显性要求
3. 推断 JD 背后的隐性期待
4. 把岗位要求映射到自己的项目经历
5. 预测高频问题
6. 标记高风险问题
7. 生成面试准备清单

#### 输出

- 公司调研笔记
- JD 拆解
- 岗位匹配证据
- 高频问题预测
- 高风险问题清单
- 准备检查清单

#### 完成标准

面试前，你已经清楚：

- 这家公司在做什么
- 这个岗位真正需要什么
- 我有哪些项目能证明匹配
- 面试官可能深挖什么
- 哪些问题最容易翻车

#### 反模式

- 不看 JD，只准备通用回答
- 只查公司新闻，但不连接岗位要求
- 只列问题，不准备回答结构
- 忽略之前已经暴露过的缺陷

### 5.4 面试后复盘室

#### 定位

面试后复盘室把真实面试转化为改进证据。

#### 触发场景

一轮真实面试刚结束。

#### 输入

- 面试轮次
- 实际问题
- 自己的回答
- 面试官反应
- 自我评分
- 面试结果，如果已经知道

#### 流程

1. 尽快记录实际问题
2. 记录自己的回答要点
3. 给回答质量打分
4. 标记强回答和弱回答
5. 分析弱回答背后的原因
6. 生成或关联能力缺陷
7. 生成训练任务
8. 更新岗位状态

#### 输出

- 面试复盘记录
- 实际问题库
- 回答评分
- 挂点分析
- 关联能力缺陷
- 关联训练任务

#### 完成标准

每个有价值的弱回答，都至少关联到一个能力缺陷或训练任务。

#### 反模式

- 只写情绪，不写事实
- 只说“答得不好”，但不分析哪里不好
- 创建“表达不行”这种过于抽象的缺陷
- 过几天才复盘，导致忘记真实问题

### 5.5 能力缺陷档案

#### 定位

能力缺陷档案记录被面试反复暴露的短板，并追踪它们是否被修复。

#### 触发场景

- 面试复盘发现弱回答
- 同类问题在多轮面试中重复出现
- 训练任务暴露了更底层的能力问题

#### 输入

- 缺陷标题
- 缺陷类型
- 证据
- 出现频率
- 严重程度
- 相关问题
- 相关岗位
- 修复状态

#### 输出

- 能力缺陷记录
- 缺陷分类视图
- 重复出现信号
- 修复状态

#### 完成标准

你能清楚看到：

- 当前最影响面试表现的短板是什么
- 它们来自哪些真实问题
- 哪些已经在训练
- 哪些已经改善

#### 反模式

- 创建太多细碎缺陷
- 缺陷没有真实证据
- 缺陷永远不更新、不关闭
- 把症状误当成根因

### 5.6 训练计划中心

#### 定位

训练计划中心把能力缺陷转化为具体可执行、可验收的修复任务。

#### 触发场景

- 某个缺陷需要修复
- 某个面试前需要针对性练习
- 某类问题需要形成稳定表达

#### 输入

- 关联缺陷
- 目标能力
- 训练任务
- 练习产物
- 验收标准
- 截止时间
- 验证结果

#### 流程

1. 从缺陷生成训练任务
2. 定义明确验收标准
3. 完成练习产物
4. 对练习结果做复核
5. 在后续准备或真实面试中验证是否改善

#### 输出

- 训练任务
- 练习产物
- 验收结果
- 验证记录

#### 完成标准

每个训练任务都有明确目标、产出、验收标准和状态。

#### 反模式

- 创建“提升沟通能力”这种不可验收任务
- 没有产物就标记完成
- 明明有紧急面试风险，却训练无关内容

## 7. 状态模型

### 7.1 岗位阶段

- `collected`：已收集
- `applied`：已投递
- `invited`：已邀约
- `preparing`：准备中
- `interviewed`：已面试
- `reviewed`：已复盘
- `rejected`：已挂
- `offer`：已拿 offer
- `paused`：暂停跟进

### 7.2 面试状态

- `scheduled`：已排期
- `preparing`：准备中
- `completed`：已完成
- `reviewed`：已复盘
- `cancelled`：已取消

### 7.3 缺陷状态

- `open`：待处理
- `training`：训练中
- `validating`：验证中
- `repaired`：已修复
- `archived`：已归档

### 7.4 训练任务状态

- `todo`：待做
- `doing`：进行中
- `reviewing`：待验收
- `done`：已完成
- `validated`：已验证
- `cancelled`：已取消

## 9. MVP 用户流程

```text
1. 从 JD 创建一个岗位机会
2. 设置阶段、优先级、风险和下一步动作
3. 岗位进入邀约或准备阶段
4. 创建面试轮次
5. 完成面试前作战 Brief
6. 完成真实面试
7. 记录实际问题和回答评分
8. 从弱回答创建能力缺陷
9. 从能力缺陷创建训练任务
10. 在下一轮面试中验证是否改善
```

## 10. v0.1 非目标

- 不做多人系统
- 不做公开发布流程
- 不做自动爬虫
- 不把 AI 分析作为必要依赖
- 不做复杂数据分析大屏
- 不做移动端原生 App
- 不做完整 CMS

## 11. 编码前待确认问题

1. 数据存储先用浏览器本地存储、Markdown 文件，还是轻量数据库？
2. 第一版更重视快速记录，还是字段完整？
3. 第一版做单页本地应用，还是做带路由的小型 Web App？
4. 最先实现 Pipeline 看板、详情表单，还是复盘工作流？
5. v0.1 是否引入 AI 辅助分析，还是先把手动工作流跑通？

## 12. 推荐第一实现切片

我建议第一段编码只做这条最短路径：

```text
新增岗位机会
  -> Pipeline 列表
  -> 岗位详情
  -> 创建面试轮次
  -> 面试后复盘
  -> 创建能力缺陷和训练任务
```

这条路径可以最快验证系统有没有真实价值。
