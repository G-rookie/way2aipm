# way2AIPM OS v0.19 后端规则层与存储适配雏形规格

## Summary

v0.19 是从“前端工作台”进入“后端规则层”的第一步。

当前系统已经能用 Markdown 存储完成求职 Pipeline、面试前后、缺陷、训练、表达、作品集、AI 辅助和节奏运营。但大量判断逻辑仍在前端，包括总控调度队列、训练闭环统计、缺陷画像、复盘评审和面试前作战态势。

这一版不引入数据库，不接入 AI API，也不迁移 Next.js。目标是先在 Node 服务里沉淀一层可复用的规则 API，并把现有 Markdown 读写函数整理成一个明确的 `storage` 适配对象，为后续 SQLite、AI 和 Next.js 迁移留出稳定接口。

## Goals

- 新增后端存储适配对象：
  - `storage.listOpportunities()`
  - `storage.getOpportunity(id)`
  - `storage.saveOpportunity(data)`
  - 覆盖现有核心实体的 list/get/save 方法
- 新增后端规则快照 API：
  - `GET /api/system-snapshot`
- `system-snapshot` 返回：
  - 总控调度队列
  - 总控调度指标
  - Pipeline 指标
  - 面试准备/复盘指标
  - 缺陷指标
  - 训练指标
  - 作品集指标
  - 节奏风险指标
- 前端加载数据时读取 `system-snapshot`。
- 总控调度队列优先使用后端返回结果，失败时保留前端本地计算兜底。
- README 当前版本更新到 `v0.19`。

## Non-Goals

- 不迁移数据库。
- 不拆成 Next.js。
- 不接入外部 AI API。
- 不移除前端兜底规则。
- 不新增删除能力。
- 不改变 Markdown 文件结构。
- 不做大规模后端拆文件。

## Backend Design

### Storage Adapter

第一版仍在 `server.mjs` 内定义：

```js
const storage = {
  listOpportunities,
  getOpportunity,
  saveOpportunity,
  ...
};
```

这样做的目的不是立即重构目录，而是让后续替换 Markdown 为 SQLite 时，有一个明确替换点。

### Rules Snapshot

新增：

```text
GET /api/system-snapshot
```

返回结构：

```json
{
  "snapshot": {
    "generatedAt": "2026-05-25T00:00:00.000Z",
    "dispatchQueue": [],
    "dispatchMetrics": {},
    "pipelineMetrics": {},
    "interviewMetrics": {},
    "reviewMetrics": {},
    "weaknessMetrics": {},
    "trainingTaskMetrics": {},
    "portfolioMetrics": {},
    "rhythmMetrics": {}
  }
}
```

### Frontend Integration

前端新增：

- `state.systemSnapshot`
- `loadData()` 读取 `/api/system-snapshot`
- `createDispatchQueue()` 优先返回 `state.systemSnapshot.dispatchQueue`
- `dispatchMetrics()` 可消费后端指标

如果后端快照读取失败，前端仍按旧逻辑运行。

## Test Plan

- `node --check server.mjs`
- `node --check public/app.js`
- `git diff --check`
- `GET /api/system-snapshot` 返回 200。
- `system-snapshot.dispatchQueue` 是数组。
- `system-snapshot.dispatchMetrics.total` 与队列长度一致。
- 前端静态资源能正常加载。
- 总控台在后端快照存在时仍可渲染。
- Markdown 读写路径不变化。

## Assumptions

- v0.19 是后端规则层第一步，不追求一次迁完所有前端规则。
- v0.20 将基于后端规则层定义 AI 输入输出 schema 和人工确认机制。
