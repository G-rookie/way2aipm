# way2AIPM OS v0.26 LangGraph 受控复盘闭环试点规格

## Summary

v0.26 将 v0.25 已通过的 LangGraph 对照验证推进为一条可运行的复盘闭环试点：

```text
WorkflowRun
  -> orchestrator node
  -> review_specialist node
      -> 创建/复用 AI 分析记录
      -> 触发现有 Responses API 诊断路径
  -> approval_gate interrupt
  -> 人工 accept_all / defer
  -> approval_commit node
      -> 调用现有 candidate-actions
      -> 创建缺陷与训练任务
```

试点继续保留现有 Node 服务、Markdown 领域记录与页面人工流程。LangGraph 只编排受控步骤，不取代业务实体，也不把 checkpoint 作为业务事实。

## Goals

- 复用现有正式 AI 诊断 API 和人工候选采纳 API，不复制领域写入逻辑。
- 将生成候选能力只注入 `review_specialist` 节点，将采纳写入能力只注入审批后的 `approval_commit` 节点。
- 增加磁盘持久 checkpoint，使运行在审批 interrupt 后可由新的 runner 进程继续。
- 用 `WorkflowRun.id` 作为 LangGraph `thread_id`，保持运行状态与领域流程的一对一关联。
- 验证重复恢复或重复批准不会重复生成缺陷与训练任务。
- 通过本地 Responses 协议桩验证实际 `run-ai` 请求路径，不要求测试使用真实 API key。

## Non-Goals

- 不在 v0.26 把 LangGraph 启动按钮加入页面。
- 不扩展面试前 Agent、训练 Agent 或总控自动路由。
- 不自动批准 AI 候选。
- 不用 checkpoint 替换 Markdown 存储。
- 不为业务数据引入数据库。

## Runtime Boundary

### Node Capabilities

| 节点 | 允许能力 | 写入边界 |
| --- | --- | --- |
| `orchestrator` | 无外部工具，仅确认目标流程 | 无写入 |
| `review_specialist` | 读取流程/复盘、创建或复用 AI note、调用 `run-ai` | 只保存待审批分析记录与候选 |
| `approval_gate` | `interrupt()` | 无写入 |
| `approval_commit` | 对已生成候选调用既有 `candidate-actions` | 仅在 resume 明确为 `accept_all` 后创建业务记录 |

### Persistence

- 新增 JSON 文件 checkpointer，基于 LangGraph `BaseCheckpointSaver` 接口。
- 默认正式试点状态路径建议为本地忽略目录 `runtime/langgraph/checkpoints.json`。
- 自动烟测使用 `tmp/langgraph-v026/checkpoints.json`，完成后逐个删除自己的测试文件。
- JSON saver 仅适合单机、低并发试点；部署或并发场景应迁移官方 SQLite/Postgres saver。

### Model Configuration

既有配置保持不变：

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
```

新增可选的本地开发覆盖项：

```dotenv
# OPENAI_RESPONSES_URL=http://127.0.0.1:4362/v1/responses
```

未配置时始终请求官方 `https://api.openai.com/v1/responses`。覆盖项用于本地协议验证或未来受控代理，不在前端暴露。

## Pilot Commands

应用服务运行且已配置模型后，可针对已有 `WorkflowRun.id` 启动试点：

```powershell
$env:WAY2AIPM_BASE_URL='http://localhost:4173'
$env:WAY2AIPM_LANGGRAPH_CHECKPOINT_PATH='D:\code\way2aipm\runtime\langgraph\checkpoints.json'
node integrations/langgraph/review-pilot-runner.mjs start <workflowRunId>
```

当输出显示等待审批后，显式恢复：

```powershell
node integrations/langgraph/review-pilot-runner.mjs resume <workflowRunId> accept_all
node integrations/langgraph/review-pilot-runner.mjs resume <workflowRunId> defer
```

`accept_all` 会采纳本次生成的缺陷和训练候选；`defer` 不创建业务记录。

## Acceptance Criteria

- 启动运行会通过现有 `run-ai` 接口生成一条待确认 AI note，并进入 LangGraph interrupt。
- interrupt 前不产生能力缺陷或训练任务。
- 新 runner 进程能从磁盘 checkpoint 恢复同一 `WorkflowRun.id`。
- `accept_all` 后只生成一组缺陷与训练任务，流程进入 `training_pending`。
- 再次对同一完成线程执行 resume，或模拟写入后状态回写中断再重试，均不产生重复记录。
- 本地 smoke test 的模型请求走 Responses API 请求结构，并不读取真实密钥。
