# way2AIPM OS v0.24 受控 Agent 执行链路验证规格

## Summary

v0.24 在 v0.23 已验证的 OpenClaw Tool Plugin 与 Lobster 审批底座之上，验证最小 Agent 结构是否成立：

```text
orchestrator
  -> review_specialist
  -> way2aipm_review_context
  -> way2aipm_propose_review_diagnosis
  -> approval required
```

本版本不将 Lobster 强行嵌入领域流程，也不迁移 `WorkflowRun` 的状态所有权。鉴于已安装 OpenClaw 文档说明嵌入式 Lobster runner 内的嵌套 `openclaw.invoke` 当前不可靠，v0.24 首先验证 Agent 委派和受控工具边界。

执行结果见 [v0.24 OpenClaw 受控 Agent 执行链路验证记录](v0.24-openclaw-agent-validation.zh.md)。

## Goals

- 配置 `orchestrator` 与 `review_specialist` 两个隔离 Agent 工作区。
- 验证总控 Agent 只能委派，不读取或写入业务内容。
- 验证复盘专项 Agent 只能读取复盘上下文并提交待审批候选。
- 通过真实 OpenClaw Agent loop 跑通一条 `diagnosis_pending` 临时流程。
- 保证实验不创建缺陷、训练任务或 AI 留痕，不改变 `WorkflowRun` 状态。

## Non-Goals

- 不引入真实模型密钥作为自动化验证的前置条件。
- 不让 Agent 采纳候选或完成领域流程。
- 不把 Lobster 的恢复 token 映射成 `WorkflowRun` 状态。
- 不将 Agent 工作区作为正式个人记忆目录。
- 不扩大 Runtime 到面试前准备、作品集或节奏模块。

## Validation Design

### Agent Roles

| Agent | 职责 | 允许工具 | 明确禁止 |
| --- | --- | --- | --- |
| `orchestrator` | 接收一个 `WorkflowRun.id` 并委派复盘诊断 | 目标上仅需 `sessions_spawn`、`sessions_yield`、`session_status` | 目标上不应获得领域工具、文件工具、shell、网络浏览 |
| `review_specialist` | 读取上下文并生成待审批诊断提案 | `way2aipm_review_context`、`way2aipm_propose_review_diagnosis` | session 委派、文件工具、shell、通用 HTTP、业务写入 |

### Deterministic Local Model Stub

自动化烟测使用本地 OpenAI-compatible 模型桩，而不是正式模型：

- 它仅根据验证场景返回预设 tool calls。
- 它不做真实诊断质量判断。
- 它让 OpenClaw 真实执行 agent session、子 Agent 委派和插件工具调用。
- 正式模型效果评估应作为后续独立验证，不混入权限/状态实验。

### State Ownership

| 状态 | 所有者 | v0.24 行为 |
| --- | --- | --- |
| 复盘与工作流业务记录 | way2AIPM | 临时创建并在测试后逐个清理 |
| 诊断候选校验 | way2AIPM Tool Adapter | 返回 `approval.required`，不持久化 |
| Agent session 与执行日志 | OpenClaw 隔离 Runtime | 写入 `tmp/openclaw-v024/` |
| 审批暂停/恢复 | Lobster 候选能力 | 本版不接入 Agent 委派链路 |

## Security Boundary

- Runtime 配置、session 和本地模型桩状态只位于忽略目录 `tmp/openclaw-v024/`。
- 插件 API token 与 Gateway token 由烟测临时随机生成（或由进程环境覆盖），不写入受跟踪文件。
- `plugins.allow` 仅包含本项目受控插件。
- 实验 Agent 配置 `skills: []`，不向模型注入与验证目标无关的技能。
- 工具策略显式拒绝 `group:fs`、`group:runtime`、`group:web`、`browser`、`canvas`、`cron`、`gateway` 与 `message`。
- 本地烟测不要求 Docker sandbox，因此只验证工具暴露和领域写入边界；使用真实求职材料前仍需验证容器 sandbox 或等价宿主隔离。
- 若 OpenClaw 的子 Agent 继承父 Agent allow 边界导致专项工具无法仅向子 Agent 授权，则将其记录为验证结论，不将指令约束伪装成权限隔离。

## Deliverables

- 两个 Agent 的工作区操作指令。
- 可重复运行的本地 Agent 委派烟测。
- 隔离 Runtime 配置和工具策略说明。
- 真实执行结果与 v0.25 决策输入。

## Acceptance Criteria

- OpenClaw 能识别两个 Agent，并让 `orchestrator` 发起一次 `review_specialist` 子任务；若严格权限配置无法执行，必须给出可复现实验证据。
- 专项 Agent 通过插件读取一条 `diagnosis_pending` 流程并校验候选。
- 返回结果停在 `approval.required`，`WorkflowRun.status` 仍为 `diagnosis_pending`。
- 测试前后 AI note、缺陷和训练任务数量不变化。
- 自动验证不依赖公开网络或真实模型密钥。

## Follow-Up

- 若 Agent 委派链路通过，下一版本验证真实模型在相同工具限制下的候选质量与稳定性。
- Lobster 与领域审批的连接只在找到不依赖不可靠嵌套调用的方式后继续。
- 直到审批与幂等状态同步完整通过，现有人工采纳流程保持正式路径。
