# v0.25 LangGraph 针对性对照验证记录

## 状态

- 日期：`2026-05-27`
- 分支：`codex/feature-langgraph-evaluation-v0.25`
- 实际依赖：`@langchain/langgraph@1.3.2`（由 `package-lock.json` 固定）
- 当前结论：`prefer_langgraph_controlled_workflow_pilot`

## 验证目标

v0.24 已证明 OpenClaw 能调用受控工具，但其原生子 Agent 继承父级工具允许边界，无法满足严格角色工具隔离。本轮使用同一条复盘诊断候选路径验证 LangGraph 是否可以做到：

```text
orchestrator node (no domain adapter)
  -> review_specialist node (read/propose only)
  -> approval_gate interrupt
  -> resume with human defer decision
```

本次只比较编排与边界，不评价真实模型生成质量。

## 实现方式

新增隔离实验目录：

```text
integrations/langgraph/
  package.json
  package-lock.json
  workflow-interrupt-smoke-test.mjs
```

烟测行为：

1. 启动临时 way2AIPM 本地服务。
2. 通过现有 API 创建一条临时 `diagnosis_pending` `WorkflowRun` 及必要关联记录。
3. 创建仅含两个受控方法的复盘 adapter，并只将它注入 `review_specialist` 节点。
4. 以 `WorkflowRun.id` 作为 LangGraph `thread_id` 运行图。
5. 在 `approval_gate` 中调用 `interrupt()`，确认第一次执行停在人工审批前。
6. 以 `Command({ resume: { decision: "defer" } })` 恢复同一线程。
7. 验证恢复前后均没有 AI note、缺陷或训练任务写入，并逐个清理测试记录。

### 能力隔离边界

| 节点 | 可达能力 | 验证结果 |
| --- | --- | --- |
| `orchestrator` | 无领域 adapter，仅返回调度状态 | 通过 |
| `review_specialist` | `readReviewContext`、`proposeReviewDiagnosis` | 通过 |
| `approval_gate` | `interrupt()` 与待审批 state | 通过 |
| `finalize_deferred` | 记录本次 defer 结果 | 通过 |

这里的严格隔离来自节点构造与依赖注入，而不是依赖提示词要求总控“不要调用”它已经持有的工具。未来接入 LLM 节点时，仍需保证模型的工具绑定遵循同一节点边界。

## 执行结果

执行命令：

```powershell
npm.cmd run smoke --prefix D:\code\way2aipm\integrations\langgraph
```

实际输出：

```json
{
  "runtime": "langgraph",
  "strictNodeToolIsolation": true,
  "orchestratorTools": [],
  "reviewSpecialistTools": [
    "readReviewContext",
    "proposeReviewDiagnosis"
  ],
  "threadMatchesWorkflowRun": true,
  "interrupted": true,
  "resumedDecision": "defer",
  "workflowStatus": "diagnosis_pending",
  "approval": "required",
  "written": false,
  "deltas": {
    "notes": 0,
    "weaknesses": 0,
    "tasks": 0
  },
  "checkpointer": "MemorySaver-local-validation-only"
}
```

已证明：

- 总控节点无需持有复盘领域工具即可推进到专项节点。
- 复盘节点可以独占读取与提案校验能力。
- `interrupt` 可以可靠停在审批前，并以同一 `WorkflowRun.id` 线程恢复。
- 受控提案仍返回 `approval.required` 与 `persistence.written=false`。
- 恢复选择 `defer` 后，`WorkflowRun.status` 保持 `diagnosis_pending`，领域记录变化为零。

## 仍未验证

- 当前使用 `MemorySaver`，仅证明同进程本地恢复；未验证进程重启后的持久 checkpoint。
- 当前节点使用确定性 fixture，不代表真实模型的候选质量、延迟和错误处理已满足使用要求。
- 当前验证的是审批前和 defer 路径；人工采纳后如何幂等写回现有领域 API，仍需在试点版本完成。
- 当前验证在 Node 小服务上成立，未来 Next.js 或数据库迁移仍需保持 Tool Adapter 和审批边界不被破坏。

## 技术结论

LangGraph 直接满足了本项目对受控业务流程编排最关键的结构要求：不同节点可以获得不同能力集合，人工审批可以成为图内的明确中断点，而 `WorkflowRun` 仍保持领域事实所有权。

因此不再继续扩张 OpenClaw 原生子 Agent 作为正式闭环编排路线。OpenClaw 插件和 Lobster 验证结果仍作为工具协议与审批能力参考保留；正式 Runtime 推进方向改为 **LangGraph 受控复盘闭环试点**。

## 下一步

`v0.26` 应聚焦于一条真实可用的复盘闭环试点：

- 固化 LangGraph 节点与现有 `WorkflowRun` 的状态映射。
- 选择适合本地使用的持久 checkpoint 方案，验证重启后恢复。
- 将真实复盘诊断触发纳入受控图，但继续保留人工采纳写入边界。
- 验证失败重试与重复 resume 不会重复创建领域记录。
