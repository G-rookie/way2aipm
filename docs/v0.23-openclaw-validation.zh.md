## 官方能力核对

根据 OpenClaw 官方文档，当前与本项目有关的候选能力包括：

| 能力 | 官方资料结论 | way2AIPM 用途 |
| --- | --- | --- |
| Node 环境 | 推荐 Node `24` 或要求 Node `22.19+`；Windows 可运行，WSL2 更稳定 | 判断本机验证路径 |
| Multi-Agent Routing | 不同 Agent 可拥有独立 workspace、session 与 tools | 总控 Agent 与复盘专项 Agent 隔离 |
| Sub-Agents | 主执行可派发子 Agent 工作 | 总控向复盘诊断委派 |
| Task Flow | 持久化多步骤工作流，可追踪状态并恢复 | 映射修复闭环执行过程 |
| Lobster approval/resume | 可在关键步骤等待批准并使用 token 恢复 | 候选采纳前停止自动执行 |
| Sandbox / tool policy | workspace 不是安全边界，需显式限制工具权限 | 防止 Runtime 越过领域 API |

这些能力目前仅用于决定验证方向。是否适配 `WorkflowRun`，仍必须通过本地运行实验确认。

## 已实现边界

v0.23 先在 way2AIPM 侧建立一个窄且可测试的 Tool Adapter：

| 能力 | Endpoint | 行为 |
| --- | --- | --- |
| 工具清单 | `GET /api/agent-tools/manifest` | 返回权限策略和可暴露工具 |
| 读取流程复盘上下文 | `GET /api/agent-tools/workflow-runs/{id}/review-context` | 返回流程、复盘、提示词与结构化输出 schema |
| 校验复盘诊断提案 | `POST /api/agent-tools/review-diagnosis-proposals/validate` | 仅校验候选并返回待审批状态 |

所有端点要求：

```dotenv
WAY2AIPM_AGENT_TOOL_TOKEN=本地长随机令牌
```

访问要求 `Authorization: Bearer <token>`。未配置令牌时端点不可用；未认证时拒绝访问。

### 明确不提供的能力

- 不提供创建 `Weakness` 的 Agent 工具。
- 不提供创建 `TrainingTask` 的 Agent 工具。
- 不提供更新或关闭 `WorkflowRun` 的 Agent 工具。
- 不授予 Runtime 对 `content/` 的文件写权限。
- 不应向 Runtime 暴露任意 HTTP、shell 或通用文件工具，否则它可能绕过窄接口访问现有业务 API。

## 桥接客户端与插件

新增零依赖桥接客户端：

```text
integrations/openclaw/way2aipm-tool-client.mjs
```

它从根目录 `.env.local` 读取令牌，并仅调用上述 Agent Tool Adapter 端点：

```powershell
node integrations/openclaw/way2aipm-tool-client.mjs manifest
node integrations/openclaw/way2aipm-tool-client.mjs context <workflowRunId>
node integrations/openclaw/way2aipm-tool-client.mjs propose <workflowRunId> integrations/openclaw/fixtures/review-diagnosis-proposal.example.json
```

桥接客户端用于直接检查 API 边界；Runtime 接入使用新增插件包：

```text
integrations/openclaw/plugin/
```

该插件采用官方 `defineToolPlugin` 形式，并经 `openclaw plugins build` 与 `openclaw plugins validate` 通过验证。它仅注册两个 `optional` 工具：

| OpenClaw 工具 | 对应边界 | 是否写入 |
| --- | --- | --- |
| `way2aipm_review_context` | 读取复盘流程上下文 | 否 |
| `way2aipm_propose_review_diagnosis` | 校验待审批候选 | 否 |

插件只允许连接 loopback HTTP URL。OpenClaw 的安装安全扫描会阻止“源码直接读取环境变量后发送 HTTP”的实现，因此插件读取 `config.apiToken`，隔离 Runtime 配置通过字符串 `${WAY2AIPM_AGENT_TOOL_TOKEN}` 注入私密值，不在跟踪文件中落入令牌。

## 已执行验证

### 语法与格式

```powershell
node --check server.mjs
node --check integrations/openclaw/way2aipm-tool-client.mjs
node --check integrations/openclaw/runtime-smoke-test.mjs
git diff --check
```

结果：通过。

### 认证与无写入验证

测试过程：

1. 在隔离端口启动当前 Node 服务。
2. 未配置 Agent token 请求 manifest。
3. 配置 token 后，以未认证请求再次访问。
4. 使用桥接客户端读取 manifest 与一条临时 `WorkflowRun` 的复盘上下文。
5. 使用示例候选提交提案校验。
6. 检查流程状态，以及 AI note、缺陷和训练任务数量。
7. 逐个删除为验证创建的临时 Markdown 记录。

实际结果：

```json
{
  "access": [503, 401, 200],
  "clientTools": [
    "get_workflow_review_context",
    "propose_review_diagnosis"
  ],
  "workflowStatus": "diagnosis_pending",
  "approval": "required",
  "before": {
    "notes": 0,
    "weaknesses": 0,
    "tasks": 0
  },
  "after": {
    "notes": 0,
    "weaknesses": 0,
    "tasks": 0
  }
}
```

结论：

- 令牌保护按设计拒绝未配置和未认证访问。
- 桥接客户端能消费只读上下文与提案校验端点。
- 提案返回等待人工审批，不推进 `WorkflowRun`。
- 提案不会生成 AI note、缺陷或训练任务记录。

### OpenClaw Plugin 与 Gateway 工具调用

执行内容：

1. 依据已安装官方 SDK 构建 `way2aipm-controlled-tools` 插件。
2. 运行 `openclaw plugins validate` 校验 manifest 与两个 optional tools。
3. 在隔离 Runtime 配置中 link 插件，仅 allowlist 两个工具。
4. 通过 `integrations/openclaw/runtime-smoke-test.mjs` 启动临时服务与 Gateway。
5. 通过 Gateway `POST /tools/invoke` 调用两个工具，并逐个清理测试 Markdown 记录。

实际输出：

```json
{
  "tool": "get_workflow_review_context",
  "workflowStatus": "diagnosis_pending",
  "approval": "required",
  "written": false,
  "deltas": {
    "notes": 0,
    "weaknesses": 0,
    "tasks": 0
  }
}
```

结论：

- 原生 Windows 下，隔离 OpenClaw Gateway 能加载本项目的受控 Tool Plugin。
- Runtime 经工具策略只能读取上下文并提交候选，无法直接推进领域流程。
- 当前“等待人工确认”的边界由 way2AIPM API 响应和现有 UI 承担，已经被真实 Runtime 调用证明。

## Task Flow / Lobster 边界

本轮没有将 `Task Flow` 或 Lobster 描述为完成，原因如下：

- 当前隔离 Runtime 中执行 `openclaw plugins inspect lobster --runtime --json` 返回 `Plugin not found: lobster`。
- OpenClaw 自带官方外部插件目录将审批工具标记为独立包 `@openclaw/lobster`，当前尚未安装。
- 已安装版本文档明确说明：嵌入式 Lobster runner 中，使用 `openclaw.invoke` 再调用 Gateway 工具当前不可靠。

因此，`way2AIPM Tool Plugin -> Gateway` 的接入可继续采用 OpenClaw；但不能直接假定 Lobster 能编排我们的两个插件工具。后续应先独立验证 Lobster 自身的 `needs_approval` / resume 行为，再判断其与领域流程的连接方式。

## 下一实验步骤

1. 独立安装 `@openclaw/lobster` 到隔离 Runtime，并验证一个不触及业务数据的审批暂停/恢复样例。
2. 配置总控 Agent 与复盘专项 Agent，以两个已验证工具运行一条 `diagnosis_pending` 流程。
3. 确认 Agent 运行过程中未获得 shell、通用文件写入或任意业务 API 调用权限。
4. 若 Lobster 无法可靠调用本项目工具，在 v0.24 保留 way2AIPM `WorkflowRun` 为唯一编排状态，并仅把 OpenClaw 用作受控 Agent 执行层。

在完成 Agent 与审批编排验证前，不采用 OpenClaw 作为正式闭环 Runtime，现有 v0.22 手动流程继续是可靠路径。
