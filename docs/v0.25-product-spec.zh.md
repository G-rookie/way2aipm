# way2AIPM OS v0.25 LangGraph 针对性对照验证规格

## Summary

v0.25 不立即替换现有运行路径，而是针对 v0.24 暴露出的两个关键问题做对照验证：

```text
orchestrator node
  -> review_specialist node
  -> way2AIPM read/propose adapter
  -> approval interrupt
  -> human resume
```

本版本验证 LangGraph 是否能够以显式节点依赖的方式实现严格工具隔离，并用 `interrupt` / `Command({ resume })` 表达人工审批暂停与恢复。`WorkflowRun` 仍是领域事实来源，图运行状态不是 Markdown 业务记录的替代品。

## Why Now

v0.24 的真实 OpenClaw 子 Agent 实验已经证明：

- 受控 Tool Plugin 与无业务写入边界可行。
- 原生子 Agent 会继承父 Agent 的工具允许边界，无法满足“总控不持有复盘工具”的严格角色隔离。
- 使用 `sessions_yield` 等待专项任务时出现 session 写锁竞争。

因此 v0.25 只比较造成决策差异的能力，不扩大功能范围。

## Goals

- 复用同一条面试后诊断候选流程与同一份候选 fixture。
- 将 `orchestrator` 节点构造为不接收领域适配器的纯调度节点。
- 只向 `review_specialist` 节点注入读取上下文与校验候选的受控能力。
- 通过 LangGraph `interrupt` 暂停在人工决策前，并以同一 `thread_id` 恢复。
- 将 `thread_id` 与一条唯一 `WorkflowRun.id` 关联，验证恢复不会造成业务记录写入。
- 保持 AI note、缺陷、训练任务以及 `WorkflowRun.status` 在验证期间不变化。

## Non-Goals

- 不引入真实模型或评价诊断内容质量。
- 不实现人工采纳后的正式写入流程。
- 不将 MemorySaver 作为生产级持久化方案。
- 不将全部 OS 模块改造成 LangGraph 节点或 Agent。
- 不决定公开部署、数据库迁移或 Next.js 改造方案。

## Validation Design

### Node Boundaries

| 节点 | 输入能力 | 行为 | 明确不具备 |
| --- | --- | --- | --- |
| `orchestrator` | 无领域 adapter | 记录调度并将流程导向复盘节点 | 复盘读取、提案校验、业务写入 |
| `review_specialist` | `readReviewContext`、`proposeReviewDiagnosis` | 读取现有复盘并提交候选校验 | 人工采纳、缺陷/训练创建 |
| `approval_gate` | LangGraph `interrupt` | 向外暴露待审批候选并等待恢复 | 业务写入 |
| `finalize_deferred` | 无领域 adapter | 记录本次未采纳决定并结束运行 | 业务写入 |

本次隔离验证的含义是：领域 adapter 仅通过闭包注入专项节点，总控代码没有取得工具对象的路径。后续接入真实 LLM 时，也必须沿用每节点独立绑定工具的结构并重新验证。

### State And Resume

- 图运行以 `workflowRun.id` 作为 `thread_id`。
- `review_specialist` 返回 API 已校验的候选对象，结果必须为 `approval.required` 和 `persistence.written=false`。
- `approval_gate` 调用 `interrupt()`，首次运行必须暂停。
- 烟测以 `Command({ resume: { decision: "defer" } })` 恢复同一线程。
- 本版只验证“不采纳”恢复路径；采纳写入继续由现有页面人工流程持有。

### Data Boundary

- 烟测仅通过已有 API 创建一组临时 opportunity、interview、review 与 workflow run。
- 临时记录路径由脚本基于 API 返回 id 明确跟踪，结束后逐个删除。
- 受控 adapter 只调用 v0.23 已有的 `review-context` 与 `review-diagnosis-proposals/validate` 接口。
- API token 在进程内随机生成，不保存到受跟踪文件。

## Deliverables

- 独立的 `integrations/langgraph/` 实验包与运行说明。
- 可重复执行的 interrupt/resume 烟测。
- 节点工具可达性、线程映射与无领域写入的验证记录。
- 基于验证结果更新的 Runtime 决策与 Roadmap。

## Acceptance Criteria

- `orchestrator` 工具可达集合为空，`review_specialist` 仅具有两个受控 adapter 方法。
- 第一次图调用返回待审批 interrupt，恢复调用使用相同的 `WorkflowRun.id` 线程。
- 校验候选停在 `approval.required`，且提案 API 明确返回未写入。
- 恢复后 `WorkflowRun.status` 仍为 `diagnosis_pending`。
- AI note、缺陷和训练任务的前后数量差均为零。
- 验证不依赖真实模型 API key 或外部模型调用。
