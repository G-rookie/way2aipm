# way2AIPM OS v0.21 正式 AI 复盘诊断接入规格

## Summary

v0.21 在 v0.20 已有的结构化候选与人工确认机制之上，接入第一条正式模型调用链：

```text
面试复盘
  -> 保存复盘诊断分析记录
  -> 用户主动调用 AI
  -> 服务端发送当前复盘上下文与提示词
  -> Responses API 返回严格 JSON
  -> 系统解析为缺陷与训练候选
  -> 用户逐条采纳或忽略
```

本版仍坚持：AI 输出是建议，采纳动作才会写入能力缺陷或训练任务 Markdown。

## Goals

- 使用服务端自动读取、且不纳入 Git 的 `.env.local` 配置正式 AI 调用：
  - `OPENAI_API_KEY`
  - `OPENAI_MODEL`
- 仓库只提交 `.env.example` 配置模板，不提交真实密钥与运行时模型选择。
- 使用 OpenAI `Responses API` 和严格 JSON Schema 输出复盘诊断结果。
- 新增 API：
  - `POST /api/ai-analysis-notes/:id/run-ai`
- 只允许 `review_diagnosis + interview_review` 使用正式调用。
- 模型调用成功后复用 v0.20 的结构化解析和人工采纳链路。
- AI 分析记录保留调用元数据：
  - `aiProvider`
  - `aiModel`
  - `aiRunStatus`
  - `aiLastRunAt`
  - `aiError`
- 前端提供显式的“调用 AI 生成候选”动作，并提醒发送前检查敏感信息。
- 未配置密钥或模型请求失败时给出可理解的错误，手动粘贴流程不受影响。

## Non-Goals

- 不在浏览器中保存或传递 API Key。
- 不自动触发模型调用。
- 不自动采纳、覆盖或删除任何业务记录。
- 不扩展到 JD 拆解和面试前 Brief；这些进入 v0.22。
- 不引入数据库、Next.js 或第三方 npm 依赖。

## API Flow

### `POST /api/ai-analysis-notes/:id/run-ai`

- 读取已保存的复盘诊断分析记录。
- 若提示词为空，则服务端基于所关联复盘重新生成上下文和提示词。
- 服务端调用 OpenAI Responses API，并要求返回 `review_diagnosis_v1` JSON Schema。
- 成功时将结构化输出写回 AI 分析 Markdown，并生成 `pending` 候选。
- 响应包含更新后的 `aiAnalysisNote`，不包含密钥。

失败规则：

- `.env.local` 未完整配置 `OPENAI_API_KEY` 或 `OPENAI_MODEL`：返回清晰配置提示，不发送请求。
- 请求被模型服务拒绝或没有结构化内容：返回错误；不生成候选。
- 调用失败会在分析记录中留下失败状态与时间，便于回看与重试。

## Safety And Privacy

- 只有用户点击调用按钮时，当前分析上下文才会发送给已配置的 OpenAI 服务。
- 页面在动作附近提示先检查公司、面试与个人敏感信息。
- 密钥与模型选择只从本地 `.env.local` 读取，不写入 Markdown，也不返回前端。
- 模型生成的候选永远需要用户点击“采纳”后才进入真实缺陷或训练计划。

## Test Plan

- `node --check server.mjs`
- `node --check public/app.js`
- `git diff --check`
- `.env.local` 缺失必要配置时调用接口，确认返回可理解的配置错误且服务不崩溃。
- 使用本地模拟 Responses API，确认：
  - 服务端发送严格 JSON Schema 请求。
  - 有效结构化结果生成待确认候选。
  - 模型元数据写入 AI 分析 Markdown。
- 确认手动粘贴并解析 JSON 的旧流程仍可使用。
- 确认模型调用不会直接生成 weakness 或 training task 文件。
