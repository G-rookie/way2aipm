# way2AIPM OS v0.7 总控调度器规格

## Summary

v0.7 聚焦原始 OS 结构中的 `00_总控调度器`。

这一版不做复杂自动化，也不引入 AI 自动判断，而是把分散在各模块里的“需要处理的事项”统一收敛到总控台，形成一个可视化的任务收件箱：

- 从岗位、面试、复盘、缺陷、训练、项目弹药、表达训练、作品集、AI 辅助分析中汇总待办。
- 按优先级、风险、截止时间和当前状态给出调度建议。
- 点击调度项可以跳转到对应模块和对应记录。
- 修复侧边栏版本号硬编码问题，避免页面仍显示旧版本。

## Goals

- 让总控台从“指标面板”升级为“每日入口”。
- 用户打开网页后，第一眼知道今天最该处理什么。
- 保持手动工作流：系统只提示和分发，不自动替用户做决定。
- 继续使用本地 Markdown 数据，不新增数据库。

## Non-Goals

- 不做登录、云同步、通知推送。
- 不做外部 AI 自动分析。
- 不做日历集成。
- 不做删除能力。
- 不做复杂规则配置界面。

## Key Changes

### 1. 统一调度队列

新增前端调度队列生成逻辑，将当前数据映射为统一的 `dispatch item`：

- `id`
- `type`
- `title`
- `meta`
- `module`
- `targetId`
- `priority`
- `severity`
- `dueAt`
- `reason`
- `actionLabel`

第一版调度来源：

- 待准备面试
- 待复盘面试
- 高风险岗位
- 有下一步动作的岗位
- 开放能力缺陷
- 进行中的训练任务
- 待稳定项目追问
- 未稳定表达训练
- 待处理作品集项目
- 待人工决策 AI 分析

### 2. 调度优先级

第一版使用轻量规则：

- `critical`：高风险、逾期、已完成面试但未复盘、AI 输出待决策。
- `high`：有明确截止时间、开放高严重缺陷、即将到来的面试。
- `medium`：常规下一步动作、训练任务、待处理项目。
- `low`：整理型事项或暂无截止压力的事项。

### 3. 总控台视图升级

总控台新增：

- 调度队列指标：总数、关键项、今日/逾期、待决策。
- “总控调度队列”面板，展示最重要的 12 条事项。
- 每条事项展示：标题、来源、原因、截止时间、优先级、动作按钮。
- 保留原有分模块待办面板，但让总控队列成为第一屏核心。

### 4. 跳转调度

点击调度项后进入对应模块：

- 岗位事项跳到求职中台并选中岗位。
- 面试准备跳到面试前作战室并选中面试。
- 面试复盘跳到面试后复盘室。
- 缺陷、训练、项目、追问、表达训练、作品集、AI 分析跳到对应工作台。

### 5. 版本显示修复

新增前端版本常量：

```js
const APP_VERSION = "v0.7";
```

侧边栏品牌副标题改为基于该常量渲染，不再硬编码 `v0.2 Markdown 工作台`。

README 当前版本同步更新为 `v0.7`。

## Test Plan

- `node --check public/app.js`
- `node --check server.mjs`
- 启动本地服务后访问 `http://localhost:4173`
- 空数据时总控队列显示清晰空状态。
- 有岗位 nextAction 时，总控队列出现岗位调度项。
- 有高风险岗位时，总控队列出现高优先级调度项。
- 有已完成未复盘面试时，点击能进入复盘室。
- 有 AI 输出待决策时，点击能进入 AI 辅助分析模块。
- 侧边栏显示 `v0.7 Markdown 工作台`。

## Assumptions

- v0.7 只实现本地前端调度，不新增后端存储。
- 调度项是从现有 Markdown 数据实时计算出来的派生视图。
- 后续如果需要可配置规则，再引入独立规则文件或数据库表。
