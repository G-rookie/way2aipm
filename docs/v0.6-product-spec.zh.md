# way2AIPM OS v0.6 产品规格

## 1. 版本定位

`v0.6` 的主题是：

> AI 辅助分析的第一步：只做可控建议，不做自动决策。

`v0.5` 已经把项目弹药和作品集素材整理成可展示资产。`v0.6` 开始引入 AI 辅助，但仍然遵守一个原则：

```text
本地资料
  -> 生成可审查的分析上下文
  -> 生成可复制的 AI 提示词
  -> 用户自行粘贴 AI 结果
  -> 人工确认采纳结论
  -> Markdown 留痕
```

这一版不直接调用外部 AI API，不把 AI 结果自动写入业务模块，而是先建立“有上下文、有提示词、有人工决策”的辅助分析工作台。

## 2. v0.6 目标

### 2.1 核心目标

让用户可以围绕岗位、项目、追问、复盘、缺陷、训练任务和作品集项目，生成结构化 AI 分析提示词，并把 AI 输出和自己的最终判断保存下来。

完成后，用户应该能清楚回答：

- 我这次让 AI 分析的对象是什么？
- 给 AI 的上下文是否完整、是否包含敏感信息？
- 生成的提示词要解决什么问题？
- AI 给了什么建议？
- 我最终采纳了什么、拒绝了什么、下一步怎么做？
- 这次 AI 辅助分析是否能追溯到原始资料？

### 2.2 不追求的目标

`v0.6` 仍然不做：

- 直接调用 OpenAI 或其他大模型 API
- 自动把 AI 建议写回岗位、项目、复盘或作品集
- 自动决策、自动评分、自动排序
- 聊天式多轮 AI 对话
- API Key 管理
- 外部网络请求
- 删除能力

## 3. 范围

### 3.1 本版本包含

- AI 辅助分析记录数据结构
- 分析对象来源选择
- 分析类型选择
- 自动生成上下文快照
- 自动生成可复制提示词
- AI 输出粘贴区
- 人工决策记录区
- 分析状态追踪
- 总控台展示待人工确认的 AI 分析
- Markdown 本地存储扩展

### 3.2 本版本暂不包含

- 真实 AI API 调用
- Prompt 多版本 diff
- 自动脱敏检测
- 自动生成后续任务
- 自动写回业务模块
- 批量分析
- 删除接口

## 4. 核心用户流程

```text
1. 进入 AI 辅助分析工作台
2. 选择分析类型
3. 选择分析对象来源
4. 系统生成上下文快照和提示词
5. 用户复制提示词到外部 AI 工具
6. 用户粘贴 AI 输出
7. 用户记录人工判断、采纳内容和下一步动作
8. 保存为 Markdown 留痕
```

## 5. 数据模型

### 5.1 AiAnalysisNote / AI 辅助分析记录

保存路径：

```text
content/ai-analysis-notes/{id}.md
```

字段：

- `id`
- `type`: 固定为 `aiAnalysisNote`
- `analysisType`
- `sourceType`
- `sourceId`
- `sourceTitle`
- `title`
- `contextSnapshot`
- `promptDraft`
- `aiResponse`
- `humanDecision`
- `nextAction`
- `status`
- `createdAt`
- `updatedAt`

建议枚举：

#### analysisType

- `jd_breakdown`：JD 拆解
- `company_research`：公司/业务调研
- `project_match`：项目匹配
- `follow_up_questions`：追问生成
- `answer_structure`：回答结构建议
- `portfolio_polish`：作品集文案打磨
- `weakness_repair`：缺陷修复建议
- `other`：其他

#### sourceType

- `opportunity`：岗位机会
- `project_ammo`：项目弹药
- `follow_up_question`：项目追问
- `interview_review`：面试复盘
- `weakness`：能力缺陷
- `training_task`：训练任务
- `portfolio_project`：作品集项目
- `freeform`：自由输入

#### status

- `draft`：草稿
- `prompt_ready`：提示词已就绪
- `ai_responded`：已粘贴 AI 输出
- `decided`：已人工决策
- `archived`：已归档

## 7. 页面与交互

### 7.1 AI 辅助分析工作台

新增模块：`AI 辅助分析`。

页面结构：

- 分析记录总览
- 新建分析入口
- 分析记录列表
- 分析详情表单
- 上下文快照区
- 提示词草稿区
- AI 输出粘贴区
- 人工决策区

交互要求：

- 可以选择分析类型
- 可以选择分析对象来源
- 可以从已有资料生成上下文快照
- 可以生成可复制提示词
- 可以编辑提示词
- 可以粘贴 AI 输出
- 可以记录人工决策和下一步动作
- 可以标记分析状态

### 7.2 分析上下文生成

不同来源生成不同上下文：

- `opportunity`：公司、岗位、JD、阶段、风险、下一步动作
- `project_ammo`：项目背景、目标、动作、结果、指标、AI 相关性、追问
- `follow_up_question`：追问、草稿回答、稳定回答、证据
- `interview_review`：实际问题、强弱回答、挂点分析、结果
- `weakness`：缺陷类型、证据、描述、修复状态
- `training_task`：目标能力、练习产物、验收标准、验证记录
- `portfolio_project`：公开标题、摘要、问题、方案、结果、脱敏风险
- `freeform`：用户手动填写上下文

### 7.3 提示词模板

第一版只做本地模板拼接，不做复杂 Prompt Builder。

每个提示词应包含：

- 角色设定
- 分析目标
- 上下文
- 输出格式要求
- 限制条件：只给建议，不替用户决策

## 8. API 设计

### 8.1 AI 分析记录

- `GET /api/ai-analysis-notes`
  - 支持查询：`analysisType`、`sourceType`、`status`

- `GET /api/ai-analysis-notes/:id`

- `POST /api/ai-analysis-notes`

- `PUT /api/ai-analysis-notes/:id`

### 8.2 分析上下文预览

- `POST /api/ai-analysis-context`

请求：

- `analysisType`
- `sourceType`
- `sourceId`
- `freeformContext`

返回：

- `sourceTitle`
- `contextSnapshot`
- `promptDraft`

### 8.3 删除策略

`v0.6` 继续不提供删除接口。

## 9. 状态联动

- 新建分析时默认状态为 `prompt_ready`
- 粘贴 AI 输出后可标记为 `ai_responded`
- 填写人工决策后可标记为 `decided`
- 总控台展示 `ai_responded` 但还未 `decided` 的分析记录
- 所有 AI 结果只进入 AI 分析记录，不自动写回其他模块

## 10. 验收标准

### 10.1 数据验收

- 创建 AI 分析记录后，生成 `content/ai-analysis-notes/{id}.md`
- 刷新页面后，分析记录仍能读取
- 上下文快照和提示词能从不同来源生成
- 不出现删除接口和批量文件操作

### 10.2 流程验收

- 用户能选择分析类型和来源
- 用户能生成上下文和提示词
- 用户能复制提示词到外部 AI 工具
- 用户能粘贴 AI 输出
- 用户能记录人工决策和下一步动作
- 总控台能看到待人工确认的 AI 分析

### 10.3 UI 验收

- 页面是工作台，不是聊天窗口
- 上下文、提示词、AI 输出、人工决策边界清晰
- 不暗示系统已经自动调用 AI
- 长文本不溢出、不遮挡
- 窄屏下可以完成核心编辑动作

## 12. v0.7 预告

`v0.7` 建议主题：

> 自动写回前的人工采纳机制。

它可以让用户把 AI 分析中的某一条建议手动转化为训练任务、项目追问、作品集修改项或面试准备事项，但仍保持人工确认。
