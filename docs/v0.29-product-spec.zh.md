# way2AIPM OS v0.29 公开作品集出口与 Next.js 迁移契约规格

## Summary

v0.29 将作品集从“工作台内预览”推进为有明确发布边界的独立只读展示出口：

```text
PortfolioProfile + PortfolioProject Markdown
  -> 人工设置公开发布状态与项目脱敏就绪状态
  -> /api/public-portfolio 输出脱敏只读契约
  -> /showcase.html 独立展示页消费公开契约
  -> 未来 Next.js 页面复用同一契约
```

本版不迁移现有工作台到 Next.js，也不把本地 Markdown 改为数据库。重点是先把“什么能够公开”定义成可验证的后端边界，避免未来公开页面误读内部记录。

## Goals

- 建立独立公开作品集数据契约，不让公开页面直接消费内部编辑对象。
- 使用人工发布门禁：个人资料需要设为 `published_ready`，项目同时满足 `visibility=portfolio` 与 `readiness=ready` 才能出现在公开输出中。
- 输出只保留适合展示的字段，排除素材关联、隐私检查备注、内部证据与编辑状态。
- 提供独立展示 URL `/showcase.html`，可在本地查看真实公开结果。
- 在现有作品集工作台中提供明确的公开展示入口和发布门禁状态。
- 为 Next.js 迁移记录页面/API 边界，使未来试点不影响内部工作台和 Agent 流程。

## Non-Goals

- 不部署公网环境、不实现登录、权限或分享链接。
- 不将 `public/` 单页工作台整体迁移为 React 或 Next.js。
- 不自动脱敏文本，也不让 AI 自动批准发布内容。
- 不公开 `projectAmmoId`、`projectName`、`evidence`、`privacyNote`、内部状态或 Markdown 文件路径。
- 不调整 Markdown 作为业务事实来源的当前决策。

## Publishing Gate

| 对象 | 公开条件 | 公开结果 |
| --- | --- | --- |
| 个人资料 | `portfolioStatus === "published_ready"` | 输出展示名称、定位、地点、简介、能力标签和联系说明 |
| 项目卡 | 资料已通过门禁，且 `visibility === "portfolio"`、`readiness === "ready"` | 输出经过整理的案例叙述字段 |
| 其他资料或项目 | 任一条件未满足 | 对公开 API 不可见 |

公开门禁是后端规则，不依赖页面隐藏控件。即使直接访问公开 API，也不能读取未发布或未完成脱敏的记录。

## Public Contract

`GET /api/public-portfolio` 返回稳定、只读的 `public_portfolio_v1` 契约：

```json
{
  "contractVersion": "public_portfolio_v1",
  "published": true,
  "profile": {
    "displayName": "示例姓名",
    "headline": "AI Product Manager",
    "targetRole": "AI 产品经理",
    "location": "Shanghai",
    "summary": "公开简介",
    "coreSkills": ["AI 产品设计", "用户研究"],
    "contactNote": "公开联系说明"
  },
  "projects": [
    {
      "displayTitle": "公开案例",
      "subtitle": "项目副标题",
      "role": "产品经理",
      "period": "2025",
      "summary": "案例摘要",
      "problem": "问题",
      "solution": "方案",
      "impact": "结果",
      "metrics": "公开指标",
      "skills": ["需求拆解", "实验设计"]
    }
  ],
  "stats": {
    "publishedProjects": 1
  }
}
```

资料未设置允许公开时返回 `published: false`、`profile: null`、空项目列表和零计数，不暴露草稿内容。

## UI Interaction

- 作品集产品线继续承担资料编辑、项目脱敏与本地内部预览。
- 新增“公开展示页”入口，在独立页面中只查看公开契约结果。
- 公开页在尚未发布时显示未开放状态，不渲染内部资料。
- 公开页在发布后展示个人定位、能力标签和可发布项目卡，窄屏保持可阅读。

## Next.js Migration Boundary

本版采用“契约先行”的迁移验证：

- Next.js 页面未来只消费 `public_portfolio_v1`，不读取 Markdown 目录。
- Markdown 解析、门禁判断、脱敏投影仍属于服务端存储/领域层。
- 首次 Next.js 试点只迁移公开展示页，不迁移内部 OS 工作台、AI Runtime 或写入 API。
- 若未来需要部署，Next.js 可以通过服务端适配层读取同一契约，之后再讨论 SQLite 或云存储。

## Acceptance Criteria

- 公开 API 在资料未发布时不返回任何资料或项目内容。
- 公开 API 仅返回同时通过展示与就绪门禁的项目。
- 公开输出不含内部关联 ID、隐私备注、内部证据或状态字段。
- `/showcase.html` 能正确展示未发布状态和已发布项目页面。
- 内部工作台可访问公开展示页，同时仍保留原本编辑和预览流程。
- 自动化烟测覆盖门禁、字段白名单与只读行为；桌面及窄屏完成视觉检查。

## Follow-Up

- `v0.30` 可在该契约稳定后创建真正的 Next.js 展示应用试点，评估部署、路由与数据适配成本。
- 公网发布前仍需确定身份信息、联系方式、案例指标和图片素材的公开规则。
