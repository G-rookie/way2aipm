# v0.26 LangGraph 受控复盘闭环试点验证记录

## 状态

- 日期：`2026-05-27`
- 分支：`codex/feature-langgraph-review-pilot-v0.26`
- 实际依赖：`@langchain/langgraph@1.3.2`、`@langchain/langgraph-checkpoint@1.0.2`
- 当前结论：`controlled_review_pilot_validated`

## 验证目标

v0.25 已证明 LangGraph 能隔离节点能力并暂停审批。v0.26 进一步验证一条贴近真实使用的闭环：

```text
既有 WorkflowRun
  -> 调用既有 AI 诊断 API 生成候选
  -> 写入可审查 AI note
  -> 持久 checkpoint 中断等待人工审批
  -> 新 runner 恢复并 accept_all
  -> 既有 candidate-actions 幂等生成缺陷/训练任务
```

## 实现

### 持久 checkpoint

新增 `JsonFileCheckpointSaver`，实现 LangGraph `BaseCheckpointSaver` 所需的读取、写入、pending writes 与线程删除方法：

```text
integrations/langgraph/json-file-checkpoint-saver.mjs
```

它将图运行状态保存到单个本地 JSON 文件，并使用临时文件重命名完成单次原子替换。该实现面向单用户本地试点，不宣称提供多进程并发写保障，也不承担领域业务存储。

### 受控图与 runner

新增：

```text
integrations/langgraph/review-pilot-graph.mjs
integrations/langgraph/review-pilot-runner.mjs
```

节点边界：

| 节点 | 注入能力 | 行为 |
| --- | --- | --- |
| `orchestrator` | 无 | 只调度到复盘专项节点 |
| `review_specialist` | `generateForWorkflow` | 创建/复用 AI note 并调用现有 `run-ai` |
| `approval_gate` | `interrupt` | 暂停并暴露待审批候选 |
| `approval_commit` | `acceptAll` | 仅在明确 `accept_all` 后调用现有采纳 API |

### 模型协议验证

`server.mjs` 支持可选的 `OPENAI_RESPONSES_URL` 本地配置覆盖。默认仍固定使用官方 Responses API；烟测将其指向本地协议桩，以验证实际请求结构，而不使用真实 key 或发送面试内容到网络。

只应将该覆盖项配置为可信服务地址，因为服务端会向配置地址发送模型凭据和分析上下文。

## 执行结果

命令：

```powershell
npm.cmd run smoke:pilot --prefix D:\code\way2aipm\integrations\langgraph
```

输出：

```json
{
  "runtime": "langgraph",
  "persistentCheckpoint": true,
  "runnerRestartResume": true,
  "realDiagnosisApiPath": true,
  "modelRequests": 1,
  "statusAtInterrupt": "candidate_confirmation",
  "statusAfterApproval": "training_pending",
  "decision": "accept_all",
  "repeatResumeStatus": "completed",
  "idempotentWriteback": true,
  "interruptedWriteReplayStableIds": true,
  "deltasAtInterrupt": {
    "notes": 1,
    "weaknesses": 0,
    "tasks": 0
  },
  "deltasAfterApproval": {
    "notes": 1,
    "weaknesses": 1,
    "tasks": 1
  },
  "checkpoint": "JsonFileCheckpointSaver-local-pilot"
}
```

已证明：

- 图运行可以经过现有正式 AI API 路径生成候选，并将 AI note 留作人工审查记录。
- 审批前不存在能力缺陷或训练任务写入。
- interrupt 状态写入磁盘后，新的 runner 进程可以用同一 `WorkflowRun.id` 恢复。
- 人工批准后复用既有 candidate-actions 写入一份缺陷与一份训练任务。
- 已完成线程再次收到相同恢复操作时，不会重复创建领域记录，也不会再次调用模型。
- 候选生成实体使用稳定 ID；即使模拟实体写入成功而候选状态尚未落盘，重试采纳仍命中原记录。

## 限制

- `JsonFileCheckpointSaver` 是单机试点实现；并发执行、崩溃写竞争或云部署前，应更换为官方数据库 saver。
- 本轮以本地 Responses 协议桩验证真实 API 调用链路，不评价正式模型输出质量。
- runner 当前通过命令行启动和审批，页面还没有显示 Runtime interrupt 或恢复操作。
- `accept_all` 是最小闭环验证动作；实际使用还需要支持单条采纳/忽略。

## 结论与下一步

LangGraph 已满足进入产品交互集成前的关键条件：工具职责隔离、持久审批恢复、现有模型调用复用和批准写回幂等均有自动验证证据。

`v0.27` 应将试点能力接入 Workflow 页面：展示 Runtime 状态，允许用户发起诊断、逐条审批与恢复失败流程；面试前专项 Agent 顺延到该闭环在真实使用中稳定之后。
