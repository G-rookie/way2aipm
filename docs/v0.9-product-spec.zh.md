# way2AIPM OS v0.9 个人节奏运营官规格

## Summary

v0.9 聚焦原始 OS 结构中的 `09_个人节奏运营官`。

这一版先做本地节奏记录工作台，用来记录求职过程中的精力、负荷、恢复、日程压力和当天重点。它不是健康管理 App，也不是复杂日历，而是帮助你在高压求职期长期跑得动：

- 记录每天/阶段性的精力状态。
- 识别高负荷与恢复不足。
- 把“需要调整节奏”的事项汇入总控调度队列。
- 给面试、训练、复盘之外的长期可持续性留一个位置。

## Goals

- 补齐 `个人节奏运营官` 模块。
- 使用本地 Markdown 存储节奏记录。
- 在总控台展示恢复风险和调整事项。
- 让节奏运营和求职闭环并行，而不是等到崩掉才处理。

## Non-Goals

- 不接日历 API。
- 不做自动提醒。
- 不做健康诊断。
- 不做统计图表和长期趋势分析。
- 不做删除能力。

## Data Model

保存路径：

```text
content/rhythm-logs/{id}.md
```

字段：

- `id`
- `type`
- `date`
- `title`
- `energyLevel`
- `focusLevel`
- `loadLevel`
- `recoveryLevel`
- `sleepHours`
- `interviewLoad`
- `trainingLoad`
- `plannedFocus`
- `recoveryAction`
- `rhythmRisk`
- `nextAdjustment`
- `notes`
- `status`
- `updatedAt`

枚举：

`energyLevel` / `focusLevel` / `recoveryLevel`

- `low`
- `medium`
- `high`

`loadLevel` / `rhythmRisk`

- `low`
- `medium`
- `high`

`status`

- `planned`：计划中
- `active`：执行中
- `recovery_needed`：需要恢复
- `closed`：已收尾
- `archived`：已归档

## UX

新增侧边栏模块：

```text
09 节奏运营官
```

页面结构：

- 顶部指标：记录总数、需要恢复、高负荷、低精力。
- 左侧：节奏记录列表。
- 右侧：节奏记录详情表单。
- 支持新增记录。
- 支持记录当天重点、恢复动作、下一步调整和备注。

## Dashboard Integration

总控调度队列新增来源：

- 状态为 `recovery_needed` 的节奏记录。
- `loadLevel=high` 且 `energyLevel=low` 的节奏记录。
- 有 `nextAdjustment` 且未关闭的节奏记录。

点击调度项进入节奏运营官并选中对应记录。

## API

- `GET /api/rhythm-logs`
- `GET /api/rhythm-logs/:id`
- `POST /api/rhythm-logs`
- `PUT /api/rhythm-logs/:id`

第一版不提供删除接口。

## Test Plan

- `node --check server.mjs`
- `node --check public/app.js`
- 创建一条节奏记录后，确认生成 Markdown 文件。
- 刷新后，确认记录能重新读取。
- 修改状态、风险、恢复动作后，确认 front matter 更新。
- 总控调度队列能显示需要恢复 / 高负荷低精力 / 有调整动作的节奏记录。
- 点击总控调度项能进入节奏运营官并选中记录。

## Assumptions

- v0.9 只做本地手动记录。
- 节奏记录是求职 OS 的运营层，不替代日历或健康工具。
- 后续如果需要长期趋势，再在 v1.x 增加统计视图。
