## 本轮交付

- Workflow 详情新增 `受控 AI Runtime` 区域，可在网页启动复盘诊断、查看待审批状态并提交逐条决定。
- 服务端新增三条 Runtime API：查询状态、启动诊断和恢复审批。
- LangGraph `approval_gate` 支持逐条 `accept` / `ignore`，并校验训练任务与关联缺陷的采纳依赖。
- `approval_commit` 继续复用现有 `candidate-actions`，只有明确采纳项才进入 Markdown 业务记录。
- 模型调用失败后可重新点击启动，复用既有分析记录继续运行。
- 页面品牌版本已同步为 `v0.27`，避免页面仍显示旧 Runtime 建设阶段的版本号。

## 已证实边界

- 页面启动诊断后，Runtime 会在候选生成完成时进入人工审批中断。
- 审批前领域增量写入为零；AI note 仅作为可审查候选留痕。
- 页面可以单独采纳缺陷并忽略训练任务；非法的“忽略缺陷但采纳其训练任务”会被服务端拒绝。
- 已完成运行再次收到恢复请求时返回既有结果，不会生成重复记录。
- 首次模型请求临时失败后，重新启动能够复用原 note 并重新进入待审批状态。
- 使用本地 Playwright 在 `1440 x 1100` 桌面视口和 `390 x 1100` 窄屏视口检查待审批页面，Runtime 候选、选择控件与提交按钮不存在溢出或遮挡。

## 限制与下一步

- Runtime 当前仍面向本地单用户，JSON checkpoint 不承担并发写入或公开部署要求。
- 页面提供的是复盘诊断闭环，不是开放式 Agent 对话或自动路由系统。
- `v0.28` 进入面试前专项 Agent，继续沿用“生成建议、人工确认、再写入”的受控模式。
