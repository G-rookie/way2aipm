# way2AIPM OS v0.28 面试前专项 Agent 规格

## Summary

v0.28 在面试前作战室接入首条 `Preparation Specialist` 受控运行路径：

```text
InterviewRound + Opportunity + 可用项目弹药
  -> 页面发起面试前准备建议
  -> LangGraph preparation_specialist 调用模型生成 Brief 建议字段
  -> approval_gate interrupt 等待人工确认
  -> 页面逐项选择“采纳建议”或“保留现有内容”
  -> approval_commit 更新/创建 PreInterviewBrief
```

本版让 Agent 参与准备材料整理，但不允许它未经确认直接覆盖 Brief。现有 Markdown Brief 继续是面试前准备的业务事实，Runtime checkpoint 只保存尚待审批的运行状态。

## Goals

- 在面试前作战室中为所选面试轮次提供 `Preparation Specialist` Runtime 入口。
- 使用岗位 JD、面试轮次以及状态为“可用于面试”的项目弹药生成结构化 Brief 建议。
- 建议覆盖以下领域：JD 拆解、隐性期待、项目匹配、风险缺口、高频问题、高风险问题与准备清单。
- 在页面中逐项展示建议，用户必须明确选择采纳或保留现有内容后才能提交。
- 审批提交后复用现有 Brief Markdown 存储路径；没有 Brief 时创建草稿，已有 Brief 时仅覆盖被采纳字段。
- 保持模型失败可重试、完成后重复提交不重复创建 Brief。

## Non-Goals

- 不让 Agent 自动发起公司外部搜索或编造公司信息。
- 不自动将 Brief 标记为“已准备完成”；采纳建议后状态仍由用户判断。
- 不自动创建项目弹药、训练任务或表达训练。
- 不实现多 Agent 路由、长期记忆、数据库迁移或公开部署。
- 不替代页面中已有的手工编辑 Brief 能力。

## Proposal Fields

模型生成的候选字段采用 `preparation_brief_v1` 结构：

| 字段 | 页面含义 | 主要上下文 |
| --- | --- | --- |
| `jdRequirements` | JD 拆解 | JD 原文、岗位信息 |
| `hiddenExpectations` | 隐性期待 | JD 与轮次推断，必须标明推断 |
| `matchingEvidence` | 匹配证据 | 可用项目弹药中的事实 |
| `riskGaps` | 风险缺口 | JD 要求与已有证据差距 |
| `projectMapping` | 项目经历映射 | 可用项目弹药 |
| `questionPredictions` | 高频问题预测 | 岗位、轮次与项目素材 |
| `highRiskQuestions` | 高风险问题 | 风险差距与追问点 |
| `prepChecklist` | 准备清单 | 可执行 Markdown checklist |

公司调研、业务理解和产品理解仍可由用户手动补充。本版不调用外部检索，避免把无依据的公司事实写入 Brief。

## Runtime API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/api/interviews/:id/preparation-runtime` | 返回所选面试轮次的 Runtime 摘要。 |
| `POST` | `/api/interviews/:id/preparation-runtime/start` | 基于本地上下文生成建议并暂停等待审批。 |
| `POST` | `/api/interviews/:id/preparation-runtime/resume` | 提交每个建议字段的人工决定并写回 Brief。 |

提交审批请求：

```json
{
  "action": "commit",
  "decisions": [
    { "field": "jdRequirements", "action": "accept" },
    { "field": "riskGaps", "action": "keep" }
  ]
}
```

规则：

- 必须为返回的每个建议字段选择 `accept` 或 `keep`。
- `accept` 将建议值更新到 Brief 对应字段。
- `keep` 不修改已有字段；当新建 Brief 时对应字段保持空白。
- 完成线程再次收到恢复请求时只返回既有结果，不重复创建 Brief。

## Runtime Boundary

| 节点 | 能力 | 写入边界 |
| --- | --- | --- |
| `orchestrator` | 选择面试前专项节点 | 无写入 |
| `preparation_specialist` | 读取岗位/面试/项目上下文并请求结构化建议 | 无 Brief 写入 |
| `approval_gate` | `interrupt()` 与审批完整性校验 | 无写入 |
| `approval_commit` | 将采纳字段应用到既有 Brief API/领域方法 | 仅审批后写入一份 Brief |

线程 ID 使用 `preparation:{interviewRoundId}`，避免与面试后 `WorkflowRun.id` Runtime 混淆；二者可共用 Git 忽略的本地 checkpoint 文件。

## UI Interaction

- 没有 Brief 时仍可直接启动建议，审批后自动建立一份草稿 Brief。
- 已有 Brief 时，Runtime 建议位于表单之前，用户可以比较建议与现有编辑内容。
- 待审批区域以字段卡展示建议文本和选择控件；全部选择后才开放提交按钮。
- 完成后显示采纳字段数量和 Brief 更新状态，手工表单继续可编辑。
- 请求失败通过 toast 告知并保留重试入口。

## Acceptance Criteria

- 页面可以针对一个面试轮次启动 Preparation Runtime 并展示结构化字段建议。
- interrupt 前 `content/pre-interview-briefs/` 没有新增或修改。
- 部分采纳会创建/更新唯一 Brief，并只落入被采纳字段。
- 已有 Brief 中选择保留的字段不会被建议覆盖。
- 重复恢复已完成线程不会生成第二份 Brief 或重复修改内容。
- 模型请求失败后可重新启动并继续进入待审批状态。
- 桌面和窄屏下建议卡、选择控件与 Brief 表单均可正常阅读操作。
