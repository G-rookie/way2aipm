# way2AIPM OS v0.3 产品规格

## 1. 版本定位

`v0.3` 的主题是：

> 把真实面试转化为可追踪、可修复、可验证的成长资产。

`v0.2` 已经覆盖：

```text
岗位机会
  -> 面试轮次
  -> 面试前作战 Brief
```

`v0.3` 继续补齐面试后的闭环：

```text
真实面试
  -> 面试后复盘
  -> 实际问题记录
  -> 挂点分析
  -> 能力缺陷
  -> 训练任务
  -> 下一轮验证
```

这一版的核心不是“写一篇复盘”，而是把每一次面试里的弱信号沉淀成可以行动的修复任务。

## 2. v0.3 目标

### 2.1 核心目标

让用户可以在一轮面试结束后，围绕该轮面试完成结构化复盘，并从复盘中生成能力缺陷和训练任务。

完成后，用户应该能清楚回答：

- 这轮面试实际问了哪些问题？
- 哪些回答是强回答，哪些回答是弱回答？
- 弱回答背后的原因是什么？
- 这个问题是否已经重复出现过？
- 它对应什么能力缺陷？
- 应该用什么训练任务修复？
- 下一轮面试如何验证是否改善？

### 2.2 不追求的目标

`v0.3` 仍然不做：

- AI 自动复盘
- 自动生成训练计划
- 语音录音或转写
- 自动爬取面试反馈
- 复杂数据图表
- 公开展示页
- 删除能力

## 3. 范围

### 3.1 本版本包含

- 面试后复盘数据结构
- 实际问题记录
- 回答质量评级
- 强回答与弱回答记录
- 挂点分析
- 面试结果记录
- 从复盘创建或关联能力缺陷
- 从能力缺陷创建训练任务
- 总控台展示待复盘面试、开放缺陷、进行中训练任务
- 缺陷与训练中心从占位变成真实工作区
- Markdown 本地存储扩展

### 3.2 本版本暂不包含

- AI 自动分析
- 独立问题库产品化
- 项目弹药库独立模块
- 表达稳定性训练室独立模块
- 多轮面试趋势图
- 复杂搜索
- 批量导入或批量删除

## 4. 核心用户流程

```text
1. 一轮面试完成
2. 在面试轮次中标记为 completed
3. 进入面试后复盘室
4. 创建该轮面试的复盘
5. 记录实际问题
6. 给回答质量打分
7. 标记强回答和弱回答
8. 分析弱回答背后的挂点
9. 从挂点创建或关联能力缺陷
10. 从能力缺陷创建训练任务
11. 后续面试中验证缺陷是否改善
```

## 5. 数据模型

### 5.1 InterviewReview / 面试复盘

保存路径：

```text
content/interview-reviews/{id}.md
```

字段：

- `id`
- `type`: 固定为 `interviewReview`
- `opportunityId`
- `interviewRoundId`
- `companyName`
- `roleTitle`
- `roundName`
- `actualQuestions`
- `strongAnswers`
- `weakAnswers`
- `failurePoints`
- `interviewerSignals`
- `selfRating`
- `result`
- `summary`
- `linkedWeaknessIds`
- `linkedTrainingTaskIds`
- `status`
- `createdAt`
- `updatedAt`

建议枚举：

#### selfRating

- `great`：表现很好
- `good`：整体不错
- `mixed`：有好有坏
- `weak`：明显偏弱
- `failed`：严重失误

#### result

- `unknown`：未知
- `passed`：通过
- `failed`：未通过
- `pending`：等待结果
- `withdrawn`：主动放弃

#### status

- `draft`：草稿
- `reviewed`：已复盘
- `needs_followup`：需要继续追踪

### 5.2 Weakness / 能力缺陷

保存路径：

```text
content/weaknesses/{id}.md
```

字段：

- `id`
- `type`: 固定为 `weakness`
- `title`
- `category`
- `description`
- `evidence`
- `severity`
- `frequency`
- `status`
- `relatedOpportunityIds`
- `relatedInterviewRoundIds`
- `relatedReviewIds`
- `linkedTrainingTaskIds`
- `createdAt`
- `updatedAt`

建议枚举：

#### category

- `project_depth`：项目深挖不足
- `product_thinking`：产品判断不足
- `ai_understanding`：AI 理解不足
- `business_sense`：业务理解不足
- `communication`：表达结构不稳
- `case_analysis`：案例分析不足
- `motivation`：动机与匹配度不足
- `other`：其他

#### severity

- `low`：低
- `medium`：中
- `high`：高

#### status

- `open`：待处理
- `training`：训练中
- `validating`：验证中
- `repaired`：已修复
- `archived`：已归档

### 5.3 TrainingTask / 训练任务

保存路径：

```text
content/training-tasks/{id}.md
```

字段：

- `id`
- `type`: 固定为 `trainingTask`
- `weaknessId`
- `title`
- `taskType`
- `targetAbility`
- `practiceOutput`
- `acceptanceCriteria`
- `status`
- `dueAt`
- `validationNote`
- `relatedReviewId`
- `relatedInterviewRoundId`
- `createdAt`
- `updatedAt`

建议枚举：

#### taskType

- `answer_rewrite`：重写回答
- `mock_interview`：模拟面试
- `project_deep_dive`：项目深挖
- `case_practice`：案例练习
- `knowledge_patch`：知识补齐
- `expression_drill`：表达训练
- `other`：其他

#### status

- `todo`：待做
- `doing`：进行中
- `reviewing`：待验收
- `done`：已完成
- `validated`：已验证
- `cancelled`：已取消

## 7. 页面与交互

### 7.1 总控台

新增展示：

- 待复盘面试
- 开放能力缺陷
- 进行中训练任务

总控台目标：

> 打开系统后，可以快速知道哪一轮面试要复盘、哪个缺陷要修、哪个训练任务要推进。

### 7.2 面试后复盘室

从占位升级为真实编辑区域。

页面结构：

- 顶部：选择已完成或待复盘的面试轮次
- 主区域：复盘表单
- 侧边区域：关联缺陷和训练任务

复盘表单字段：

- 实际问题
- 强回答
- 弱回答
- 挂点分析
- 面试官信号
- 自我评级
- 面试结果
- 总结

交互要求：

- 选择面试轮次后，如果没有复盘，可以创建一份
- 保存复盘后写入 `content/interview-reviews/{id}.md`
- 复盘状态为 `reviewed` 时，同步面试轮次状态为 `reviewed`
- 复盘中可以快速创建能力缺陷
- 复盘中可以看到已关联的能力缺陷和训练任务

### 7.3 缺陷与训练中心

从占位升级为真实工作区。

页面结构：

- 能力缺陷列表
- 缺陷详情
- 关联证据
- 训练任务列表
- 训练任务编辑表单

交互要求：

- 能从复盘创建缺陷
- 能从缺陷创建训练任务
- 能编辑缺陷状态
- 能编辑训练任务状态
- 能看到某个缺陷来自哪些面试复盘

## 8. API 设计

### 8.1 面试复盘

- `GET /api/interview-reviews`
  - 支持查询：`opportunityId`、`interviewRoundId`

- `GET /api/interview-reviews/:id`
  - 返回单个复盘

- `POST /api/interview-reviews`
  - 创建复盘

- `PUT /api/interview-reviews/:id`
  - 更新复盘

### 8.2 能力缺陷

- `GET /api/weaknesses`
  - 支持查询：`status`、`category`

- `GET /api/weaknesses/:id`
  - 返回单个缺陷

- `POST /api/weaknesses`
  - 创建缺陷

- `PUT /api/weaknesses/:id`
  - 更新缺陷

### 8.3 训练任务

- `GET /api/training-tasks`
  - 支持查询：`weaknessId`、`status`

- `GET /api/training-tasks/:id`
  - 返回单个训练任务

- `POST /api/training-tasks`
  - 创建训练任务

- `PUT /api/training-tasks/:id`
  - 更新训练任务

### 8.4 删除策略

`v0.3` 继续不提供删除接口。

## 9. 状态联动

- 面试轮次 `completed` 后，应在总控台显示为待复盘
- 复盘保存为 `reviewed` 后，对应面试轮次状态同步为 `reviewed`
- 从复盘创建缺陷后，复盘记录追加 `linkedWeaknessIds`
- 从缺陷创建训练任务后，缺陷记录追加 `linkedTrainingTaskIds`
- 训练任务状态变为 `validated` 后，相关缺陷可以进入 `validating` 或 `repaired`

## 10. 验收标准

### 10.1 数据验收

- 创建复盘后，生成 `content/interview-reviews/{id}.md`
- 创建缺陷后，生成 `content/weaknesses/{id}.md`
- 创建训练任务后，生成 `content/training-tasks/{id}.md`
- 刷新页面后，复盘、缺陷、训练任务仍能读取
- 不出现删除接口和批量文件操作

### 10.2 流程验收

- 用户能从已完成面试进入复盘
- 用户能记录实际问题和回答表现
- 用户能从复盘创建能力缺陷
- 用户能从能力缺陷创建训练任务
- 总控台能看到待复盘、开放缺陷和训练任务

### 10.3 UI 验收

- 空数据时有明确入口
- 复盘、缺陷、训练任务之间的关联关系清晰
- 表单内容不溢出、不遮挡
- 窄屏下可以完成核心记录动作
- 页面保持工作台风格，不做营销式说明页

## 11. 建议实现切片

### Slice 1：面试复盘基础能力

- 新增 `content/interview-reviews/`
- 新增 InterviewReview API
- 面试后复盘室支持选择面试轮次
- 支持创建、编辑、保存复盘
- 总控台显示待复盘面试

### Slice 2：能力缺陷基础能力

- 新增 `content/weaknesses/`
- 新增 Weakness API
- 缺陷与训练中心支持缺陷列表和详情
- 支持从复盘创建或关联缺陷

### Slice 3：训练任务基础能力

- 新增 `content/training-tasks/`
- 新增 TrainingTask API
- 支持从缺陷创建训练任务
- 支持训练任务状态追踪

### Slice 4：状态联动与体验补强

- 复盘状态同步面试轮次状态
- 缺陷与训练任务关联回写
- 总控台强化待复盘、待修复、待训练事项
- 补充空状态和错误提示

## 12. v0.4 预告

> 项目弹药库 + 表达稳定性训练。

它会把复盘中反复暴露的问题，沉淀到项目表达、项目深挖和高频追问训练中。
