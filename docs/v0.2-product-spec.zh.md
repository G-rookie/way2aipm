# way2AIPM OS v0.2 产品规格

## 1. 版本定位

`v0.2` 的主题是：

> 从“岗位机会管理”推进到“某一轮面试怎么准备”。

`v0.1` 已经完成本地 Markdown 工作台、总控台、Pipeline 看板和岗位详情表单。  
`v0.2` 不急着做完整复盘闭环，而是补齐面试前最关键的一段：

```text
岗位机会
  -> 面试轮次
  -> 面试前作战 Brief
  -> 准备清单
```

这一版的核心目标是让每个进入面试阶段的岗位，都能生成一份结构化、可执行、可复用的面试准备材料。

## 2. v0.2 目标

### 2.1 核心目标

让用户可以围绕一个岗位创建面试轮次，并为该轮面试完成结构化准备。

完成后，用户应该能清楚回答：

- 这次是哪家公司、哪个岗位、哪一轮面试？
- 面试时间、面试类型、面试官信息是什么？
- 这家公司和业务我理解到什么程度？
- JD 要求和我的经历如何匹配？
- 哪些问题最可能被问？
- 哪些问题是高风险问题？
- 面试前还差哪些准备动作？

### 2.2 不追求的目标

`v0.2` 仍然不做：

- 面试后完整复盘工作流
- 能力缺陷和训练任务生成
- AI 自动分析
- 登录、云同步、权限系统
- Next.js 迁移
- 数据库存储
- 删除能力

## 3. 范围

### 3.1 本版本包含

- 面试轮次数据结构
- 面试轮次创建与编辑
- 岗位详情中展示关联面试轮次
- 面试前作战室从占位变成可编辑工作流
- 公司调研记录
- JD 拆解记录
- 项目经历匹配记录
- 高频问题预测
- 高风险问题标记
- 面试准备清单
- Markdown 本地存储扩展

### 3.2 本版本暂不包含

- 面试后复盘室真实功能
- 缺陷与训练中心真实功能
- 跨岗位问题库
- 项目弹药库独立模块
- AI 生成 JD 分析
- 批量导入岗位
- 批量删除文件

## 4. 核心用户流程

```text
1. 在 Pipeline 中选择一个岗位
2. 创建一轮面试
3. 填写面试轮次信息
4. 进入面试前作战室
5. 完成公司调研
6. 完成 JD 拆解
7. 映射自己的项目经历
8. 预测可能问题
9. 标记高风险问题
10. 生成准备清单
11. 回到总控台查看待准备面试
```

## 5. 数据模型

### 5.1 InterviewRound / 面试轮次

保存路径：

```text
content/interviews/{id}.md
```

字段：

- `id`
- `type`: 固定为 `interviewRound`
- `opportunityId`
- `companyName`
- `roleTitle`
- `roundName`
- `roundType`
- `scheduledAt`
- `interviewer`
- `location`
- `status`
- `preparationStatus`
- `nextAction`
- `notes`
- `createdAt`
- `updatedAt`

建议枚举：

#### roundType

`roundType` 先按真实求职中的轮次来设计，不强行区分业务面、产品面、Case 面等细分类。

- `first`：一面
- `second`：二面
- `third`：三面
- `hr`：HR 面
- `final`：终面
- `other`：其他

#### status

- `scheduled`：已排期
- `preparing`：准备中
- `completed`：已完成
- `reviewed`：已复盘
- `cancelled`：已取消

#### preparationStatus

- `not_started`：未开始
- `drafting`：整理中
- `ready`：已准备
- `needs_rework`：需要补强

### 5.2 PreInterviewBrief / 面试前作战 Brief

保存路径：

```text
content/pre-interview-briefs/{id}.md
```

字段：

- `id`
- `type`: 固定为 `preInterviewBrief`
- `opportunityId`
- `interviewRoundId`
- `companyResearch`
- `businessSummary`
- `productSummary`
- `jdRequirements`
- `hiddenExpectations`
- `matchingEvidence`
- `riskGaps`
- `projectMapping`
- `questionPredictions`
- `highRiskQuestions`
- `prepChecklist`
- `status`
- `createdAt`
- `updatedAt`

建议枚举：

#### status

- `draft`：草稿
- `ready`：已准备
- `needs_rework`：需要补强

## 7. 页面与交互

### 7.1 总控台

新增展示：

- 即将到来的面试
- 待准备面试
- 准备状态为 `needs_rework` 的面试

总控台的目标仍然是 30 秒内回答：

> 我现在最应该准备哪一轮面试？

### 7.2 求职中台 / Pipeline

在岗位详情中新增：

- 面试轮次列表
- 创建面试轮次按钮
- 最近一轮面试状态
- 最近一轮准备状态

岗位卡片可以显示：

- 最近面试时间
- 是否存在待准备面试

### 7.3 面试轮次表单

字段：

- 所属岗位
- 轮次名称
- 面试类型
- 面试时间
- 面试官
- 面试地点或链接
- 状态
- 准备状态
- 下一步动作
- 备注

交互要求：

- 从岗位详情创建时，自动带入 `opportunityId`、公司名、岗位名
- 保存后生成 `content/interviews/{id}.md`
- 不提供删除按钮
- 可以编辑已有面试轮次

### 7.4 面试前作战室

从占位升级为真实编辑区域。

页面结构：

- 顶部：当前岗位与面试轮次选择
- 左侧或上方：准备状态与下一步动作
- 主区域：作战 Brief 表单

Brief 表单区域：

- 公司调研
- 业务与产品理解
- JD 拆解
- 隐性期待
- 匹配证据
- 风险缺口
- 项目经历映射
- 高频问题预测
- 高风险问题
- 准备清单

交互要求：

- 选择一个面试轮次后，如果没有 Brief，可以创建一份
- 保存 Brief 后写入 `content/pre-interview-briefs/{id}.md`
- Brief 状态可以在 `draft`、`ready`、`needs_rework` 之间切换
- 保存 Brief 后同步更新面试轮次的 `preparationStatus`

## 8. API 设计

### 8.1 面试轮次

- `GET /api/interviews`
  - 支持可选查询：`opportunityId`
  - 返回面试轮次列表

- `GET /api/interviews/:id`
  - 返回单个面试轮次

- `POST /api/interviews`
  - 创建面试轮次

- `PUT /api/interviews/:id`
  - 更新面试轮次

### 8.2 面试前 Brief

- `GET /api/pre-interview-briefs`
  - 支持可选查询：`opportunityId`、`interviewRoundId`

- `GET /api/pre-interview-briefs/:id`
  - 返回单个 Brief

- `POST /api/pre-interview-briefs`
  - 创建 Brief

- `PUT /api/pre-interview-briefs/:id`
  - 更新 Brief

### 8.3 删除策略

`v0.2` 继续不提供任何删除接口。

如未来需要删除，只允许单个明确资源删除，并且必须单独讨论。

## 9. 存储层要求

`v0.2` 可以继续沿用 `server.mjs` 的 Markdown 存储方式，但建议在实现时抽出更清晰的存储辅助函数，避免 Opportunity、InterviewRound、Brief 的读写逻辑重复。

推荐抽象：

- `readMarkdownRecord(filePath)`
- `writeMarkdownRecord(filePath, frontMatter, body)`
- `listMarkdownRecords(directory, expectedType)`
- `safeRecordPath(directory, id)`

这不是为了过度设计，而是为后续迁移数据库留出边界。

## 10. 验收标准

### 10.1 数据验收

- 创建面试轮次后，生成 `content/interviews/{id}.md`
- 创建 Brief 后，生成 `content/pre-interview-briefs/{id}.md`
- 刷新页面后，面试轮次和 Brief 仍能读取
- 更新 Brief 后，Markdown 文件内容同步变化
- 不出现删除接口和批量文件操作

### 10.2 流程验收

- 用户能从一个岗位进入创建面试轮次
- 用户能从面试轮次进入面试前作战室
- 用户能为该轮面试填写并保存 Brief
- 总控台能显示待准备面试
- Pipeline 中能看到岗位关联的最近面试状态

### 10.3 UI 验收

- 空数据时有明确入口
- 有多个岗位和多个面试时，选择关系清晰
- 表单内容不溢出、不遮挡
- 窄屏下可以完成核心编辑动作
- 页面不出现“功能说明式大段文字”，而是直接提供工作区

## 11. 建议实现切片

### Slice 1：面试轮次基础能力

- 新增 `content/interviews/`
- 新增 InterviewRound 读写 API
- 岗位详情中新增面试轮次列表
- 支持创建和编辑面试轮次
- 总控台显示待准备面试

### Slice 2：面试前 Brief 基础能力

- 新增 `content/pre-interview-briefs/`
- 新增 Brief 读写 API
- 面试前作战室支持选择面试轮次
- 支持创建、编辑、保存 Brief

### Slice 3：状态联动与体验补强

- Brief 保存后同步面试轮次准备状态
- Pipeline 卡片显示最近面试状态
- 总控台强化待准备事项
- 补充空状态和错误提示

## 12. v0.3 预告

`v0.3` 建议主题：

> 面试后复盘 + 能力缺陷与训练任务闭环。

它会承接 `v0.2` 的面试轮次，把真实面试结果沉淀为：

- 实际问题
- 回答评分
- 强弱回答
- 挂点分析
- 能力缺陷
- 训练任务
- 下一轮验证
