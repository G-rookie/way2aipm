# way2AIPM OS v0.5 产品规格

## 1. 版本定位

`v0.5` 的主题是：

> 把可用于面试的项目弹药，整理成未来可以公开展示的作品集素材。

`v0.4` 已经跑通：

```text
项目弹药
  -> 项目追问
  -> 稳定回答
  -> 表达训练
```

`v0.5` 继续往外走一步：

```text
成熟项目弹药
  -> 作品集项目卡
  -> 公开展示文案
  -> 本地作品集预览
  -> 发布准备清单
```

这一版不是做完整公网发布系统，而是先把“哪些内容能展示、怎么展示、还有哪些风险没处理”变成可视化工作台。

## 2. v0.5 目标

### 2.1 核心目标

让用户可以从项目弹药库中选择成熟项目，整理成适合公开展示的作品集素材，并在本地预览一个面向 AI PM 求职展示的作品集页面。

完成后，用户应该能清楚回答：

- 我准备公开展示哪些项目？
- 每个项目对外展示的标题、摘要、角色、成果和能力标签是什么？
- 哪些项目已经可以公开，哪些还需要脱敏或补证据？
- 我的个人定位、求职方向和核心能力如何表达？
- 作品集页面看起来是否清晰、可信、适合未来公开？
- 发布前还缺哪些检查项？

### 2.2 不追求的目标

`v0.5` 仍然不做：

- 真正部署公网
- 域名、CDN、SEO 或访问统计
- 登录、权限、分享链接
- AI 自动生成作品集文案
- 复杂主题编辑器
- 图片上传或素材管理
- 删除能力

## 3. 范围

### 3.1 本版本包含

- 作品集个人资料数据结构
- 作品集项目卡数据结构
- 从 ProjectAmmo 创建作品集项目卡
- 项目公开展示状态、脱敏状态、证据状态
- 本地作品集预览页
- 作品集首页结构：个人定位、能力标签、精选项目、成长闭环
- 发布准备清单
- README 版本说明与 Markdown 存储目录更新

### 3.2 本版本暂不包含

- 真正静态站点导出
- 多主题皮肤
- 图片/附件上传
- 自动生成简历
- 自动同步到 GitHub Pages
- 多作品集版本 diff
- 删除接口

## 4. 核心用户流程

```text
1. 进入作品集产品线
2. 维护个人简介、求职方向、能力标签和联系方式占位
3. 从项目弹药库选择可用于面试的项目
4. 生成作品集项目卡
5. 编辑公开标题、项目摘要、角色、成果、能力证明和展示风险
6. 标记项目公开准备状态
7. 在本地预览作品集页面
8. 根据发布准备清单继续补齐内容
```

## 5. 数据模型

### 5.1 PortfolioProfile / 作品集个人资料

保存路径：

```text
content/portfolio/profile.md
```

字段：

- `id`: 固定为 `portfolio_profile`
- `type`: 固定为 `portfolioProfile`
- `displayName`
- `headline`
- `targetRole`
- `location`
- `summary`
- `coreSkills`
- `contactNote`
- `portfolioStatus`
- `publishChecklist`
- `createdAt`
- `updatedAt`

建议枚举：

#### portfolioStatus

- `draft`：草稿
- `reviewing`：整理中
- `ready`：可预览
- `published_ready`：具备公开准备

### 5.2 PortfolioProject / 作品集项目卡

保存路径：

```text
content/portfolio-projects/{id}.md
```

字段：

- `id`
- `type`: 固定为 `portfolioProject`
- `projectAmmoId`
- `projectName`
- `displayTitle`
- `subtitle`
- `summary`
- `role`
- `period`
- `problem`
- `solution`
- `impact`
- `metrics`
- `skills`
- `evidence`
- `privacyNote`
- `sortOrder`
- `visibility`
- `readiness`
- `createdAt`
- `updatedAt`

建议枚举：

#### visibility

- `private`：仅自己可见
- `portfolio`：进入作品集预览
- `hidden`：暂时隐藏

#### readiness

- `draft`：草稿
- `needs_sanitizing`：需要脱敏
- `needs_evidence`：需要补证据
- `ready`：可展示

## 7. 页面与交互

### 7.1 作品集产品线

新增或升级 `08_作品集产品线` 模块。

页面结构：

- 作品集状态概览
- 个人资料表单
- 候选项目列表
- 作品集项目卡列表
- 项目卡详情编辑
- 本地作品集预览入口

交互要求：

- 可以维护个人资料
- 可以从项目弹药创建作品集项目卡
- 可以编辑项目卡公开文案
- 可以标记项目卡是否进入作品集预览
- 可以标记脱敏和证据状态
- 可以调整项目展示顺序

### 7.2 本地作品集预览

作为同一个单页工作台内的预览模式，不做多页面路由。

预览结构：

- 顶部个人定位
- 个人简介
- 能力标签
- 精选项目卡
- 成长闭环摘要
- 联系方式说明

交互要求：

- 只展示 `visibility = portfolio` 的项目
- 项目按 `sortOrder` 排序
- `readiness != ready` 的项目在工作台里提示，但预览中仍可显示“待完善”状态
- 页面保持简洁、可信，不做营销落地页风格

### 7.3 发布准备清单

清单先作为文本或多行字段，不做复杂 checklist 组件。

建议检查项：

- 是否隐藏敏感公司、业务、数据
- 是否保留足够证据但不泄露隐私
- 项目结果是否真实、可解释
- 项目角色是否表述准确
- 是否有至少 2 个可展示项目
- 联系方式是否适合公开

## 8. API 设计

### 8.1 作品集个人资料

- `GET /api/portfolio-profile`
- `PUT /api/portfolio-profile`

第一版只维护单个固定 profile，不提供创建多个 profile。

### 8.2 作品集项目卡

- `GET /api/portfolio-projects`
  - 支持查询：`visibility`、`readiness`

- `GET /api/portfolio-projects/:id`
- `POST /api/portfolio-projects`
- `PUT /api/portfolio-projects/:id`

### 8.3 本地作品集预览数据

- `GET /api/portfolio-preview`

返回：

- `profile`
- `projects`
- `stats`

### 8.4 删除策略

`v0.5` 继续不提供删除接口。

## 9. 状态联动

- 从 ProjectAmmo 创建 PortfolioProject 时，默认复制项目名称、角色、周期、结果、指标、证据和 AI 相关性
- `ProjectAmmo.status = usable` 的项目优先出现在候选区
- `PortfolioProject.visibility = portfolio` 时进入预览
- `PortfolioProject.readiness != ready` 时在作品集产品线中显示风险提示
- profile 的 `portfolioStatus = ready` 时，总控台展示“作品集可预览”

## 10. 验收标准

### 10.1 数据验收

- 保存个人资料后，生成或更新 `content/portfolio/profile.md`
- 从项目弹药创建项目卡后，生成 `content/portfolio-projects/{id}.md`
- 刷新页面后，个人资料和项目卡仍能读取
- `GET /api/portfolio-preview` 能返回 profile、projects 和 stats
- 不出现删除接口和批量文件操作

### 10.2 流程验收

- 用户能维护个人定位和作品集简介
- 用户能从项目弹药创建作品集项目卡
- 用户能编辑项目卡公开展示文案
- 用户能标记项目卡展示状态和准备状态
- 用户能在工作台内看到本地作品集预览
- 用户能通过发布准备清单识别公开前风险

### 10.3 UI 验收

- 页面是工作台，不是营销落地页
- 作品集预览要比后台表单更像最终展示页，但仍保持本地预览语境
- 项目卡信息层级清晰
- 长文本不溢出、不遮挡
- 窄屏下可以完成核心编辑动作

## 12. v0.6 预告

`v0.6` 建议主题：

> AI 辅助分析的第一步：只做可控建议，不做自动决策。

它可以围绕 JD 拆解、项目匹配、追问生成、回答结构建议等环节引入 AI 辅助，但仍然保留人工确认和 Markdown 可追溯存储。
