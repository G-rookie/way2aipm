# way2AIPM OS v0.14 面试后复盘评审委员会规格

## Summary

v0.14 聚焦 `03_面试后复盘室`。

当前复盘室已经能记录实际问题、强回答、弱回答、挂点分析、面试官信号和总结，但页面仍偏表单录入。v0.14 要把这些内容组织成“复盘评审委员会”：让每次面试复盘都能快速看出记录是否完整、回答质量如何、挂点集中在哪些能力维度，以及是否应该生成能力缺陷。

这一版不新增后端字段，不改变 Markdown 存储结构，先基于现有复盘字段做前端评审视图和闭环提示。

## Goals

- 面试后复盘室新增“评审委员会”摘要区。
- 基于现有字段计算复盘完整度：
  - 实际问题
  - 强回答
  - 弱回答
  - 挂点分析
  - 面试官信号
  - 总结
- 展示回答评级概览：
  - 强回答条数
  - 弱回答条数
  - 自我评级
  - 面试结果
- 展示挂点分类建议：
  - 项目深挖不足
  - 产品判断不足
  - AI 理解不足
  - 业务判断不足
  - 表达稳定性不足
  - 其他
- 当复盘存在弱回答或挂点但未关联能力缺陷时，提示创建缺陷。
- README 当前版本更新到 `v0.14`。

## Non-Goals

- 不新增复盘字段。
- 不做 AI 自动评分。
- 不做自动生成缺陷。
- 不做复杂图表。
- 不迁移历史 Markdown。
- 不新增删除能力。

## UX

面试后复盘室右侧详情区结构：

1. 复盘评审委员会
   - 复盘完整度
   - 回答表现
   - 闭环建议
2. 复盘表单
   - 保持现有字段和保存逻辑
3. 关联能力缺陷
   - 保持现有“从本轮复盘创建缺陷”入口

完整度标签：

- 已记录
- 待补充

闭环建议：

- 如果复盘还在草稿，提示先补齐真实问题和挂点。
- 如果弱回答或挂点存在，但没有关联缺陷，提示创建能力缺陷。
- 如果已经关联缺陷，提示进入训练计划中心处理任务。

## Test Plan

- `node --check public/app.js`
- `node --check server.mjs`
- 打开面试后复盘室，确认有复盘时展示评审委员会。
- 空复盘时仍显示创建入口。
- 填写强回答、弱回答、挂点分析后，确认回答统计和挂点分类更新。
- 有挂点但没有关联缺陷时，确认出现缺陷创建提示。
- 保存复盘后，确认仍写入 `content/interview-reviews/{id}.md`。
- 窄屏下确认评审委员会和表单不重叠。

## Assumptions

- 第一版评审委员会是基于文本和枚举的启发式判断。
- 后续可以在此基础上接入 AI 辅助评分或更精细的人工评分字段。
